# 公司快速交付 PRD 使用说明

## 定位

这是一套小团队快速交付模板，不是立项报告，也不是大公司的流程审批文档。统一的是写法和关键检查项，不要求所有需求写得很长。

建议篇幅：

- 单功能迭代：3–5 页。
- 多页面版本：5–10 页。
- 完整新品：根据页面数扩展第 5 章，不额外堆背景材料。

## 分工

- 产品：确认目标、范围、流程、业务规则和验收结果。
- Agent：整理资料、生成初稿、发现缺口；不能替产品确认关键规则。
- 设计：确认页面结构、状态、交互和美术交付范围。
- 研发：确认系统行为、权限、技术依赖和降级方案。
- 测试：确认状态、异常和验收标准可执行。

## 最快使用方式

1. 产品填写第 0–4 章，先把目标、范围、流程和页面清单对齐。
2. 对每个页面重复填写第 5 章。
3. 第 6 章只写跨页面共用的规则，不在每页重复。
4. 第 7 章写可以测试的结果。
5. 第 8 章集中记录未决问题，不把猜测混入正文。
6. 评审通过后再进入原型和开发。

## 给 Agent 的标准调用方式

```text
请使用《公司快速交付 PRD 模板 v1.0》整理这次需求。

先读取我提供的产品框架、竞品截图、旧 PRD、流程图和原型：
1. 固定章节保留；不涉及的模块明确写“不涉及”。
2. 区分已确认需求、待产品确认和待研发确认。
3. 产品框架决定功能和页面范围；竞品截图只参考页面结构与控件表达。
4. 只询问会影响范围、主流程、权限、数据、商业化或异常闭环的问题。
5. 先输出 PRD 草稿和待确认问题，不直接生成原型。
6. 未得到我确认前，不把 Agent 补充内容写成正式业务规则。
```

## 进入原型的最低条件

- 目标用户和核心问题明确。
- 本期做与不做的范围明确。
- 核心流程与页面清单明确。
- 影响页面结构的关键问题已解决。
- 权限、数据和商业化已确认或明确不涉及。
- P0 功能有可验证的成功结果。

满足以上条件后，原型 Skill 才读取 PRD，生成页面画面；页面确认后，再根据同一份 PRD 生成右侧需求说明和 Axure 内容。
