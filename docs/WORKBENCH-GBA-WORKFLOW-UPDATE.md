# 根据实际新品协作更新工作台

日期：2026-10-20。本文记录从 Emulator 项目提炼的通用方法和本次工作台调整，不是该项目的业务需求副本。

## 本轮依据

读取项目当前的《新品工作流 SOP v1.0》《新品部门协作流程：试行草案》《新品自动化流程》及部门模板，结合正式 PRD、功能流程、页面与状态清单、广告位设计、验收文件作对照。

部门《静态原型评审稿输出规范》v1.6（2026-10-16）晚于 SOP（2026-10-10），需求说明按业务主题灵活分组，替代旧 SOP 固定四栏目写法。部门五阶段仍为试行流程，实际负责人和通过标准按部门确认；工作台不自行认定已通过。

历史 v1.2 送审快照、旧产品框架与过期编号用于回溯，不替代当前确认。源码及知识模板不包含项目价格、奖励时长、页面 ID、私有原型定位和用户本机绝对路径。

## 从实际资料发现的问题

旧工作台把 F1 → F2 → 埋点 → F3 当作主线，容易让文档生成取代实际原型、评审修改和研发交接。固定 3–5 页与 8,000 字上限还可能把已有完整需求截成简版。

实际资料中，多个文件虽处在正式目录，仍存在联网要求、额度消耗顺序、奖励期限和加载时机等不同口径。说明“同一目录”与“最终版文件名”都不能证明材料一致。工作台应提供可追溯对照与同步位置，不能从旧验收文件继续复制过期预期。

实际协作以当前原型为核心，流程、旁注、规则、独立 PRD 和验收相互引用。独立 PRD、状态机、Word/PDF、完整埋点与开发实测应按本轮需要使用，避免多维护一套容易落后的事实。

## 更新后的用法

主干调整为：市场和竞品分析 → 原型图＋需求说明 → 初审修改 → 终审整理 → 需求评审。从当前阶段继续，每轮明确采用的基线、任务范围与交付点，不自动跑全套。F1 五章分步生成、编辑、确认与合并保持兼容。

| 内容 | 默认或按需 | 本轮变化 |
|---|---|---|
| F1 新品分析 | 新品分析阶段使用 | 保留五章，不额外增加审批门 |
| F2 独立核心 PRD | 需求评审阶段按需 | 按模块和当前原型整理，取消固定小页数硬压缩；不替代原型阶段的交接与需求旁注 |
| 公共规则 | 按需 | 跨页面规则集中一处，稳定 RULE ID、引用与来源 |
| 功能流程与页面状态 | 按需 | 流程和定位清单合在同一交付物，不重复编号 |
| 原型制作交接 | 按需 | 给制作清单和旁注草稿，外部实际修改保持待执行边界 |
| 评审修改 | 有实际意见时使用 | 影响矩阵＋本轮修订正文，未执行产物保留待同步 |
| 全局一致性 | 终审整理或交接前按需 | 对照当前文档，不以旧快照和文件名判断一致 |
| 产品验收用例 | 需求评审准备时按需 | 模块分组，验收场景、操作步骤、预期结果三列 |
| 完整埋点 / F3 开发实测 | 可选 | 保留原能力，不强制进入主干；F3 实测证据约束不变 |

不因选择一个阶段就必须生成上述所有任务。已存在合格资料时继续使用；只有需要独立交接、同步或核对时才增补文档。

## 来源与变更同步

采用顺序：当前用户确认 → 当前实际材料或行为 → 已接受的项目文档 → 历史记录 → 通用模板。确认意图与实际画面或实现不同，明确记录差异；缺失决定不能从其他产品补造。

规则变更后执行：确认新规则 → 列影响范围 → 更新公共规则 → 同步页面图、旁注、需求、流程和验收预期 → 查找旧口径 → 复查受影响流程。只有实际完成的文件或外部修改才标为已落实。

编号同时提供中文名和稳定 ID，删除或插入内容不整体重排。简单状态在基础页表达，系统界面只说明触发与返回；复杂异步、多条件或可中断流程按需加状态转换。

自动引用已确认交付物时，按当前产品版本选择同任务最新分支；有新版待确认时，旧确认稿及其嵌套引用不会自动成为当前依据。需要对照历史资料时，可显式勾选并说明采用方式。

勾选超过 12,000 字的资料时，任务包按本轮范围选择导言、相关模块与公共规则，标明原文行号、字符位置和未读取范围。未匹配到目标模块会明确提示，不能把局部节选当成完整原文。直接从磁盘读取的当前任务模板优先于同 ID 的旧检索片段，避免旧页数限制重新混入。

## 交付与执行边界

工作台目前生成、编辑、评审与导出文档。原型制作交接是供实际连接器或操作者执行的说明，不能因此声称已经写入 Figma / Axure。现有项目、版本、来源快照与交付物不因本次更新而自动重写。

AI 自查、工作台文档确认、部门初审 / 终审 / 需求评审、静态结构读取、截图查看、真机验收与真实商业效果各自有不同证据。生成结果只声明已执行范围；不得虚构审批通过、测试结果或 ROI 改善。

本轮更新通用任务、模板、界面说明与使用文档，不修改 Emulator 私有业务文件，不迁移项目目录，不自动向外部知识库同步。GitHub 同步按用户另行授权执行。

## 2026-10-21：模板正文再次对照实际项目

本次不是只盘点文件或导出副本，而是读取 Emulator 当前《产品需求文档》《原型页面说明》《功能流程》《页面及状态编号对照表》《验收用例》、竞品分析与功能框架、部门市场分析模板及静态原型规范，再对照历史修改和终审记录更新通用正文。当前资料用于辨认表达方法与冲突，不把所有文件天然当成一致或已确认的事实。

| 实际项目体现的方法或差异 | 工作台原有不足 | 本次更新 |
|---|---|---|
| 竞品结论围绕观察、产品意义和我方取舍，参考可细到模块 | 单竞品栏目较百科化，缺候选资料并列 | 候选选用表保留下载、收入、体验与口径，用户最终选用；只对需要的问题深入，短条目表达 |
| 产品框架围绕具体用户任务与流程展开 | 通用 App 树、数量建议容易被误当要求 | 保留完整 F1 五章，取消硬凑画像、竞品数、模块数、固定商业化顺序，首版范围只详细维护一次 |
| 最新页面需求能不打开其他设计文件也读懂呈现与操作 | 通用旁注只强调条件与点击，布局表达偏弱 | 补用途、呈现形式、来源背景、区域位置层级、默认状态及完整文案；简单状态只补差异 |
| 页面编号区分页面、弹窗、局部反馈与系统说明 | 每份索引和旁注都可能重生成一套 | 复用确认页面正文、原编号和公共规则；完整 PRD 汇入同源正文，局部只改授权变化 |
| 历史复核明确发现跨页规则与文档不同步 | 多处相似同步表仍可能漂移 | 同轮一份变更表，逐条核对旧口径、确认新口径、具体位置及残留；未读和未写回分别标明 |
| 产品验收用业务编号和三列表，静态说明不等于实测 | F3 又设计少量埋点，设计表也保存实际状态 | 复用三列原用例及事件 ID，F3 只补实测；保留旧表格式，并检查新表头的无证据 PASS |

源项目本身仍有旧验收预期与当前需求/流程不一致的条目，因此本次不整份复制，也不自动修正项目。具体页面、价格、时长、期限、次数、联网策略、竞品市场数值和原型定位均不进入通用模板。

更新覆盖日常正文模板、生成约束、相关知识方法与仓库内 lifecycle skill。历史正式模板、用户已有任务正文和此前导出的 ZIP 保持原样。本次不新增审批、风险或访谈流程，也不接入新的市场数据 API；候选表只组织已有资料，不能代替实际采集和体验。

已准备但未执行的任务包仍是原快照，不会在后台被替换；要采用新版模板，需要重新准备任务。新模板不等于已完成外部原型写回、人工评审或真实 App/SDK 测试。
