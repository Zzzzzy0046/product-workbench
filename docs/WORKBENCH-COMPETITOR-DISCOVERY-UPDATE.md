# 竞品发现与新品链路优化

日期：2026-10-21。面向“先找到值得参考的产品，再决定采哪些资料”的日常新品工作，不增加机会门、正式审批或新的必填文档。

## 现在的使用路径

资料页「找竞品」→ 输入关键词、平台和国家 → 筛选候选、手动勾选 → 指定主对标／功能参考／变现参考及备注 → 调整采集范围 → 预览描述、截图和中英文评论样本 → 显式确认入库 → 带资料准备 F1 → 检查任务包后生成 → 编辑和确认 → 继续下一章。

已有商店链接时，可以直接采集，跳过搜索。新品主线后续仍是原型与需求旁注交接、真实初审修改、终审整理、需求评审准备；不为跑通流程虚构外部原型、评审意见或实测结果。

## 本轮实现

| 环节 | 行为与边界 |
|---|---|
| 找候选 | Google Play／App Store，按关键词、市场和语言读取；默认最多 12 个，后台上限 30 个。搜索不调用 Codex、不取评论、不写项目正文。 |
| 看候选 | 短卡、真实商店字段、可筛选排序；完整长短描述与截图展开后读取。缺失值不当作 0，不编造中文结论或收入。 |
| 手动选择 | 无默认勾选，最多 8 个；记录用途、备注、搜索词及发现市场。发现市场与实际采集市场分别说明。 |
| 降低等待 | 详情按需加载；公开搜索与详情按请求隔离缓存 24 小时、最多 64 条；支持刷新，错误不缓存；最多 2 个并行查询、35 秒超时。 |
| 采集预览 | 显示最多 6 张原始商店图与 5 条原文／译文评论样本，再由人确认；未确认的结果只暂存。 |
| 入库衔接 | 可显式确认当前范围内可见的就绪记录；部分失败报告已成功数量。已确认资料可一键带入 F1 准备，文本优先，超过 12 份需人工调整。 |
| 章节衔接 | 确认后继续下一章；已有下一章时查看已有记录，避免无意重复准备。五章仍由人点击合并，不调用模型重写。 |
| 输入暂存 | 任务输入仅在当前页面内存按项目、产品版本和任务隔离；最多保留 20 份，刷新清除；不保存到浏览器 localStorage。 |
| 内容时效 | 前章内容改变，后章提示需要复核；不自动重写、重跑或清除确认。再次确认仅记录已复核当前上游，正文快照不改变。合并稿不能代替逐章复核。 |
| 项目迁移 | 修复采集目录及 manifest 在导入时未按新项目、采集、版本与资料 ID 重映射的问题，保留预览与选用信息。 |

浏览器实跑另外修复：短描述可能实际是长文导致卡片过长、直接粘贴链接时空选择数组被拒绝、商店图片被页面策略拦截、空资料库重复显示“没有匹配”提示，以及确认章节后续章按钮未立即显示。图片策略仅放行本机图片、粘贴预览 blob 与 Google／Apple 图片 CDN，未放开外部脚本或 API 请求。

## 技术接入

- 搜索的 `country` 支持 `global`，合并 US、GB、DE、JP、IN、ID、BR、SA；返回实际成功/失败市场、每项 `observed_countries` 和具体 `lookup_country`。不自动选择竞品，不将全球代码传到商店接口。
- 详情仍读取具体国家；全球候选展开时使用 `lookup_country`，缺少具体市场就提示，不默认美国。
- 采集 `countries` 支持包含 `global` 并展开为八国；用户可修改组合，界面展示筛选前评论上限及最多每款 500 条翻译提示。
- `GET /api/competitors/revenue`：按 `project_id`、`version_id`、`platform`、`app_id` 读取本地人工收入资料，不请求第三方服务。
- `POST /api/competitors/revenue`：校验金额/范围、币种、周期、地区、收入类型、净毛口径、数值性质、HTTPS 来源、查看日期和明确人工确认后，保存独立 MD；不改写原始资料或现有交付物。拒绝凭证链接和未来观察日期。
- `POST /api/competitors/search`：`project_id`、可选 `version_id`、`query`、`platform`、`country`、`lang`、`limit`、`refresh`。
- `POST /api/competitors/detail`：按 `platform`、`app_id`、`country`、`lang` 读取详情。
- 原 `POST /api/competitors/collect` 保持可用；可选 `selections` 与最终去重后的竞品一一匹配，空的手填通道不要求提供选择元数据。
- Android 复用本机采集 Python 的 `google_play_scraper.search`；Apple 搜索使用标准库访问固定的官方 Search／Lookup 地址。Android 缺依赖或关闭集成时给出手填链接的退路。
- 搜索缓存只保存公开商店数据；连接凭据不进入候选、资料正文、缓存输出或项目包。

## 全球、收入入口与 UI 对齐补充

本次地区增加全球常用市场组合，不冒充全量全球搜索。搜索主行的关键词、平台、地区和按钮统一高度及基线，国家选项筛选另起一行；筛选项、候选卡与三列收入来源卡同排对齐，窄屏转为单列。

收入采用「来源入口＋复制应用 ID＋人工补充」：Sensor Tower 区分商店收入与需额外权限的广告收入；AppTweak、AppMagic 作为商店/IAP 估算来源。工作台没有读取这些服务的账号凭据、开通订阅或抓取付费接口；未获取到应用级金额时不会显示 0。来源能力按 2026-10-21 官方公开说明核对，访问权限与应用覆盖仍须用户实际核实。人工收入记录和商店描述、截图、评论可以共同作为后续分析的项目资料，但不自动成为业务结论。

## 验证方式

常规回归不发外部网络或模型请求：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -X utf8 scripts\workbench_discovery_smoke.py
.venv\Scripts\python.exe -X utf8 scripts\workbench_flow_smoke.py
```

新品发现 HTTP 冒烟使用临时项目，覆盖搜索空／失败／缓存、人工选择、用途保留、未确认不入库、预览、确认后 F1 来源、导出导入。原流程冒烟继续覆盖 F1 五章合并、后续任务、编辑批注、取消恢复、多格式导出与持久化。

真实浏览器试跑使用单独的「流程试跑-GBA竞品发现（测试）」项目，不覆盖原 GBA 项目。其公开资料与生成样例不构成正式业务决策。最新结果见 [验收记录](../workbench/VERIFICATION.md)。

## 尚未解决的问题

- 搜索候选不是完整市场，返回顺序不是市场排名；Google Play 累计安装区间不是近期下载或国家新增。
- 广告收入、近期增长、回收效果和真实广告位不能从评分、商店标记或宣传图推定，需要另有数据或实际体验。
- 商店截图与描述属于宣传证据，不等于实际流程已走查。竞品程序、设备安装、录屏、Figma／Axure 写入和业务评审不会因为本功能自动完成。
- 本轮不接商店收入数据、不做后台自动监控、不自动挑选“最佳竞品”，也不强制把所有候选都分析一遍。
