# 产品工作台下一阶段修改清单

版本：V1.0 架构修订稿  
状态：V0.9 核心路径已实施，待真实项目回归  
适用范围：本地产品工作台  

## 1. 修改目标

在不增加大型团队流程的前提下，把工作台建设成“稳定内核 + 可插拔能力”的本地产品工作平台。用户拿到工作台后，不修改主程序，就能接入自己的产品知识库并开始使用。

本轮先完成小型快速迭代团队每天会用到的五项核心能力，保持现有能力注册表和项目资料检索可用；通用插件协议不作为本轮前置条件。

具体包括：

1. 正文能够插入、管理和迁移图片；
2. 调用现有桌面工具采集竞品评论；
3. 将已确认交付物导出为 Word、PDF、Excel 和 CSV；
4. 在确认交付物前执行 F1、F2、完整埋点和 F3 轻量质量检查；
5. 完整导出、导入和迁移项目；
6. 后续再增加知识候选、检索过滤、通用插件协议和更多任务能力包。

本轮不增加付费投放、商店发布、多人实时协作、复杂权限和云端 SaaS。

## 0.9 实施说明

本轮已把五项必须能力接入同一条本地链路：图片资料上传/预览/`asset://` 插入、桌面竞品评论采集子进程、Word/PDF/Excel/CSV 渲染、F1/F2/埋点/F3 轻量校验，以及带 manifest 和 UUID 重映射的项目 ZIP 导入/导出。核心接口和自动化回归已经加入；真实网络评论采集、不同电脑的导入回归和导出视觉检查仍需要在实际项目中再跑一遍。

为控制范围，本轮没有增加检索过滤、来源过期提醒、知识候选沉淀或更多任务能力包；这些继续按后置项处理。图片删除已作为资源管理的一部分补上：有正文、历史版本或任务引用时阻止删除。

## 2. 实施顺序

```text
M1 图片与项目资源
  ↓
M2 竞品评论采集器
  ↓
M3 Word / PDF / Excel / CSV 导出
  ↓
M4 F1 / F2 / 埋点 / F3 轻量质量校验
  ↓
M5 项目完整导出与导入

第一阶段稳定后：

  ↓
M6 检索过滤与来源时效
  ↓
M7 知识候选沉淀
  ↓
M8 更多任务能力包
```

## 3. 终极形态定义

```text
产品工作台内核
├─ 项目、任务、交付物、版本与批注
├─ Knowledge Gateway（统一知识检索入口）
├─ Capability Runtime（任务能力包运行时）
├─ Tool Gateway（外部工具入口）
├─ Validator Runtime（质量规则入口）
└─ Export Runtime（导出入口）
     ↓ 统一插件协议
插件层
├─ 知识库连接器：本地目录 / Product KB MCP / 通用 MCP / 后续企业知识库
├─ 任务能力包：F1 / F2 / 埋点 / F3 / 后续专项任务
├─ 工具适配器：竞品评论爬虫 / 蓝湖 / 后续原型工具
├─ 校验器：F1 / F2 / 埋点 / F3
└─ 导出器：Markdown / Word / PDF / Excel / CSV
```

“热插拔”在本项目中明确指：

- 新增一种知识库或任务能力时，不修改 `workbench/app.py`；
- 用户可以在工作台界面完成配置、连通测试、启用、停用和重新加载；
- 插件失败不会拖垮工作台，知识源不可用时仍可使用项目资料继续工作；
- 插件有统一配置、权限、状态、错误和版本信息；
- 知识检索结果必须保留来源、定位和时间信息，不能把外部知识复制成无来源文本；
- 默认只读，任何回写都必须由插件单独声明并由用户显式触发。

这里的“马上接入”不是承诺任何知识库都能零配置自动识别，而是：工作台内置本地目录和标准 MCP 两种通用入口；符合协议的知识库可以直接配置使用，特殊系统通过独立连接器扩展。

## 4. 修改清单与执行状态

> M0 的通用插件内核和知识库连接器暂不进入本轮实施，保留在本节作为后续架构清单；M1–M5 是本轮实际交付范围。

### M0（后置）插件内核与知识库连接器

状态：`后置（保留现有注册表，标准插件协议未纳入本轮）`  
优先级：`P0 / 架构前置`  

#### 插件包规范

- [ ] 新增统一插件目录，例如 `workbench/plugins/`，插件不再散落并硬编码在 `app.py`。
- [ ] 每个插件提供 `manifest.json`，至少声明插件 ID、名称、类型、版本、入口、配置结构、权限、兼容版本和健康检查。
- [ ] 支持 `knowledge-source`、`capability`、`tool`、`validator`、`exporter` 五类插件。
- [ ] 插件 ID 全局唯一；版本不兼容、入口缺失或权限声明非法时拒绝启用。
- [ ] 支持从界面或配置目录重新扫描插件，不需要修改工作台源代码。
- [ ] 插件状态至少区分：未配置、可用、不可用、已停用、版本不兼容。
- [ ] 一个插件失败时隔离错误，不影响其他插件和工作台基础功能。

#### Knowledge Gateway 统一协议

- [ ] 定义统一知识源接口：`health`、`search`、`get`、`trace`；`sync` 与 `writeback` 为可选能力。
- [ ] `search` 统一接收 query、top_k、项目、资料类型、平台、日期和标签过滤条件。
- [ ] 统一返回 source_id、标题、原文片段、定位、来源类型、更新时间、适用范围和引用信息。
- [ ] `get` 能读取检索结果对应的原文或完整条目，避免只拿到无法核对的摘要。
- [ ] `trace` 能追溯来源文件、页面、块或外部 URL。
- [ ] 多知识源并行检索后统一去重和排序，同时保留各知识源身份。
- [ ] 项目资料优先；外部知识库用于补充方法、历史决策和案例，不覆盖项目当前事实。
- [ ] 知识源超时或失败时显示来源级错误，并允许项目资料检索继续运行。

#### 首批知识库连接器

- [ ] 内置“本地目录”连接器，允许用户选择自己的知识库文件夹。
- [ ] 支持 Markdown、TXT、文本 PDF、DOCX、CSV 等当前可解析格式。
- [ ] 内置“Product KB MCP”连接器，实际调用 `kb_search`、`kb_get`、`kb_trace` 和 `kb_find_similar_cases`。
- [ ] 提供“通用 MCP 知识库”连接器，通过配置映射 search/get/trace 等工具名。
- [ ] 后续 Notion、钉钉、飞书或 Confluence 只能作为独立连接器加入，不写进工作台内核。

#### 首次使用与配置界面

- [ ] 新增“知识源”页面，显示已安装连接器、连通状态、同步方式和最近检查时间。
- [ ] 空白安装首次打开时引导用户选择“本地目录”或“MCP 知识库”。
- [ ] 用户填写必要配置后可先执行“测试连接”，成功后再启用。
- [ ] 支持选择知识源适用范围：全局、指定项目或暂不参与自动检索。
- [ ] 任务准备页显示本次实际使用了哪些知识源，可临时取消勾选。
- [ ] 工作台自带示例知识只用于演示，可停用，不得与用户知识库混成一个来源。

#### 配置与安全

- [ ] 密钥、Token、Cookie 和账号凭证不写入插件 manifest、项目包、日志或 Git 仓库。
- [ ] 本机私密配置与可分发插件定义分开保存。
- [ ] 默认只授予读取权限；网络、文件目录、命令执行和回写权限分别声明。
- [ ] 导入外部插件时显示权限摘要，不自动执行未声明命令。
- [ ] 删除连接器只删除配置和本地索引，不删除原知识库内容。

#### 验收标准

- [ ] 一套全新工作台可以只通过界面接入一个外部产品知识库。
- [ ] 接入后无需改代码，即可在 F1、F2、埋点和 F3 准备页检索该知识库。
- [ ] 每条模型引用都能追溯到实际知识源及原文位置。
- [ ] 停用或拔掉知识库后，后续任务立即不再使用该来源，历史任务来源快照仍可查看。
- [ ] 错误配置、网络中断、MCP 进程退出不会造成项目或交付物损坏。
- [ ] 安装一个新的合规连接器后，重新扫描即可出现，不需要修改主程序。
