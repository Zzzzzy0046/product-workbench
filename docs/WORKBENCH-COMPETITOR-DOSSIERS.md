# 竞品档案与两套勾选

日期：2026-10-22。此页介绍现有产品工作台的更新，不是新增一套独立工作台。

## 使用路径

进入项目的「资料」页，在同一页面按对象查看各竞品档案与「项目公共资料」，不再切换两套分类标签。每个竞品按平台和应用 ID 建立稳定档案；名称相同的 Android 和 iOS 应用不会自动合并。竞品由使用者选择，不替使用者确定主对标。

档案分为概览与商店信息、评论、截图与流程、笔记与附件。商店宣传图、真实设备截图、模块流程图分别展示。缺失资料显示暂无，不生成虚构内容补齐。

### 采集范围

勾选竞品后点击「采集已选竞品」，选择商店信息、用户评论、中文翻译和商店截图。国家、条数和评论筛选沿用原采集表单。实机走查另需准备设备、包名和范围，不能当作一次商店图片下载。

采集完成先预览、再确认入档；待确认记录可在档案中看到，但没有作为可选原始资料进入分析。再次采集新增批次，不覆盖旧批次。采集成功不等于评论分析或竞品判断已经完成。

在档案中粘贴、拖入或上传的资料默认关联该档案。暂存队列在加入时记录归属，切换档案不会把尚未上传的文件归给另一个竞品。在项目资料首页添加、不指定竞品的文件留在「项目公共资料」分组，也可以之后批量关联到竞品；一份共同来源可关联多个档案，文件本身不复制。

### 分析输入

勾选竞品不等于全选资料。展开各竞品的资料类型，勾选本次要使用的文档或图片；同一输入区也可选择项目公共资料，不要求先选择某个竞品。也可全选当前可用资料或清空。当前单任务沿用最多 12 份输入限制，超过时明确提示，不静默丢弃文件。

「准备分析任务」只预选资料和准备任务包，不自动生成或运行模型。提交前检查竞品、文档和图片数量。通过档案勾选启动的任务使用 explicit 来源模式，不自动检索并加入其他竞品的资料。按章节生成时，任务要求的已确认前置章节作为明确衔接输入保留；不会沿用未勾选的嵌套原始资料。

任务保存具体来源快照，后来补采资料或修改档案备注不改写已有任务。新的分析需要重新选择资料。

## 归属和兼容

- 竞品档案是项目级对象，不随每个产品版本复制。
- 分析资料遵守现有版本范围：通用项目资料与当前版本资料可选，其他版本不自动混入。
- 用完整历史采集记录及其资料清单做一次性关联迁移，不只看页面最近 12 条采集记录。
- 不能从结构化来源确认归属的旧文件保留为未分配，不按文件名模糊猜测。
- 归档竞品或解除资料关联不删除原文件，不改变 document ID 与 asset 图片引用。
- 完整项目导出新增 schema 3，保留档案、共享归属及资料批次；仍可导入 schema 1、2 的旧项目包。
- 导入时重映射项目、竞品、资料、采集与版本 ID；项目回收恢复保留原 ID 和归属。

## 目标与文档预设

不再默认附加固定回收周期、收益目标或放行门槛。目标以用户本轮输入为准。历史上传资料和已生成文档保持原样；真实留存口径与普通的来源核对规则不因此删除。

## 开发入口

- `workbench/services/competitor_service.py`：档案身份、资料归属、迁移和显式输入校验。
- `workbench/static/features/competitor_dossiers.js`：档案页与两套独立勾选。
- `workbench/adapters/review_scraper.py`：采集批次、采集选项和确认入档。
- `workbench/services/job_service.py`：explicit 来源快照与任务准备。
- `workbench/services/export_service.py`、`project_service.py`：完整导入导出和回收恢复。

HTTP：`GET /api/competitors?project_id=...&version_id=...`、`GET /api/competitors/<id>?project_id=...&version_id=...`；写操作沿用本机工作台的来源和 token 检查。`POST /api/competitors/inputs` 只验证明确传入的竞品和资料 ID，不自行添加输入。`POST /api/prepare` 支持 `source_selection_mode: "explicit"`、`competitor_ids` 和 `document_ids`。
