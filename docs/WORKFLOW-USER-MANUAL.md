# 小型出海 App 新品工作流使用手册

版本：V0.7

## 一句话说明

把已经决定要做的新品和现有资料，依次变成三份中文交付物：

```text
F1 新品需求分析 → F2 核心 PRD → F3 开发验收清单
```

这不是机会筛选或正式立项流程。快速模式不要求用户访谈，不生成假设验证、风险清单、技术 Spike、Gate 或条件闭环。

## 输入什么

- 产品名称和方向；
- 目标平台、团队和本轮周期；
- 指定竞品；
- 竞品评论 CSV；
- 政策来源；
- 技术日志；
- 竞品或现有产品截图；
- 已有研究资料、PRD 或其他文档。

支持 MD、TXT、CSV、JSON、文本 PDF、DOCX、PNG、JPG、JPEG、WEBP。扫描 PDF 需要先 OCR。

## F1 新品需求分析

F1 不是一页定义卡，而是恢复到 Heart Rate 新品分析的完整产品结构：

1. 文档信息与核心结论；
2. 项目背景与资料索引；
3. 行业与市场背景；
4. 用户分层、场景和需求；
5. 3–5 个直接竞品的功能、评论、页面和商业化差异；
6. 产品定位、价值主张、首次价值和再次使用；
7. V0 现在做、后置和不做；
8. 产品功能框架；
9. 4–8 个核心模块的产品方案；
10. 启动、核心任务、再次使用和商业化流程；
11. 商业化策略；
12. 进入核心 PRD 的页面与功能。

F1 不生成平台、权限、数据或政策独立章节。具体页面确实依赖权限时，放到 F2 对应页面说明，不在新品分析中展开。

目标用户可以根据竞品场景和资料直接描述，不以访谈为前置。所有勾选资料必须进入资料索引并在相关结论中使用。默认控制在 12,000–16,000 个中文字符：保留完整产品判断，但不扩展成正式立项研究包。

## F2 核心 PRD

只写当前版本真正要开发的页面或功能：

- 目标和进入方式；
- 页面结构与控件行为；
- 数据和业务规则；
- 成功反馈、失败和恢复；
- 必要英文 UI copy；
- 参考竞品/截图以及我们的差异；
- 可执行验收标准。

默认 3–5 个核心页面，最多 8,000 个中文字符。F1 已经说清楚的市场、用户和竞品背景只引用，不重复。

## F3 开发验收清单

开发前填写操作和预期；有构建后继续填写：

- 实测结果和状态；
- 日志、截图、录像或测试报告；
- 问题、负责人和修改结果；
- 复测证据；
- 是否可以继续开发或进入内部测试。

埋点只在项目需要时填写，默认 5–8 个核心事件。计划和实测使用同一份文档，最多 5,000 个中文字符。

## 怎么运行

1. 打开 `http://127.0.0.1:8765`；
2. 新建或进入项目；
3. 上传资料；
4. 选择 F1、F2 或 F3；
5. 勾选最多 12 份要写进文档的资料；
6. 生成并检查任务包；
7. 开始生成；
8. 如果要指定位置修改，把鼠标移到正文的章节、段落或表格旁，点击「添加批注」；
9. 选择新增、修改、删除、压缩或保留，填写具体意见；
10. 点击「按 N 条批注精确修订」，生成带父任务和来源版本的新修订任务；小改也可以直接编辑 Markdown 并保存为新版本；
11. 修订版成功生成后，参与修订的批注会自动标记解决；检查新版后再评审确认，供下一份交付物引用。

## 怎么修改已经生成的交付物

生成结果后有三种修改方式：

- 小范围调整：点击「编辑正文」，直接修改正文。每次保存都会生成 V2、V3 等新版本；
- 指定位置让模型修改：在对应章节、段落、引用、表格或代码块旁添加批注，再点击「按 N 条批注精确修订」；
- 整份文档需要重写：填写「整份文档评审」，记录整体修改意见，再点击「按意见准备修订版」。

定位批注会绑定创建时的文档版本。每条批注包含位置、原文、修改动作、意见、提出人和处理状态；旧版本批注不会驱动当前版本修订。批注本身不进入交付物正文。只有修订任务成功生成完整新版后，参与该次修订的批注才会自动标记解决；生成失败不会改变批注。

当前版本还有待处理批注，或正文引用了任务快照中不存在的 `[Sx]` 时，工作台会阻止确认。快速模式 F3 的结果仍为 `Conditional` 时，需要继续在同一份清单补充修改和复测，变为通过后再确认。

点击「版本记录」可查看旧版，并将任意旧版恢复为新的当前版本。恢复不会删除中间版本。已确认文档发生编辑或恢复后，会自动回到待评审状态，避免未经复核的新内容直接成为后续任务依据。

## 怎么删除项目

进入「项目背景」，在页面底部点击「删除这个项目」，输入完整项目名称后确认。系统会阻止删除仍有生成任务运行或排队的项目。

删除前会自动保存完整本地备份，包括项目背景、原始资料、任务记录、交付物、全部版本和批注。备份位于 `workbench/data/trash/<时间>-<项目ID>/`。删除后项目不再出现在工作台，可从侧栏「项目回收站」恢复。永久删除回收备份时需要再次输入完整项目名称，且之后无法恢复。

## 怎么整理任务记录

- 默认只显示每条修订分支的最新版；
- 可以切换到全部、需要处理、已确认、待执行、待评审或已归档；
- 任务详情会显示生成时使用的快速/完整模式；切换项目模式不会改写历史任务；
- 归档任务只影响列表展示，不会删除任务包、来源快照或交付物；
- 已取消、执行失败或服务重启中断的任务都可以恢复为待执行。

## 什么时候使用完整模式

只有明确需要历史 0–12 章、正式投资评审或大型跨团队研究包时才使用正式 T1–T4。普通的“完整新品分析”使用现在的 F1；它已经包含 Heart Rate 式完整产品分析，只是不增加风险、假设验证、Spike 和 Gate。

## 不包含

- 付费投放和媒体采买；
- 投放归因；
- ASO 文案和商店素材；
- Google Play / App Store 发布执行；
- 默认用户访谈计划；
- 默认技术 Spike 和风险管理流程。
