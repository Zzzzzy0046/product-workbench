# 小型出海 App 新品工作流使用手册

版本：V1.1｜2026-10-20

## 一句话说明

把已经决定要做的新品和现有资料，按当前阶段整理成可评审、可交接的中文产物。日常主干采用五个业务阶段：

```text
市场和竞品分析 → 原型图＋需求说明 → 初审修改 → 终审整理 → 需求评审
```

每阶段可以连续完成本轮任务，业务评审由实际负责人确认。已有资料、原型或评审意见时，直接进入对应阶段，不强制从头跑完整套流程。快速模式不要求用户访谈，不生成假设验证、风险清单、技术 Spike、Gate 或条件闭环。

默认只维护产品方案、原型与需求、验收预期三类内容；它们可放在已有产物里。公共规则、流程与页面清单等在需要独立交接或核对时再生成，避免把同一规则复制成多份互相矛盾的文档。

目标与评价方式按你本轮输入决定，不默认增加固定回收周期、收益目标或放行门槛。已经提供的经营指标仍可按需引用；本次默认规则调整不会批量改写已有项目背景、资料或历史文档。

| 当前要做什么 | 在工作台选择什么 | 本轮交付 |
|---|---|---|
| 尚未选好对标产品 | 资料 → 找竞品 | 手选的竞品及主对标／功能参考／变现参考用途，之后再采集资料 |
| 从方向和指定竞品做新品分析 | F1 五章，逐章生成与确认 | 新品分析与产品范围 |
| 已有原型，需要独立 PRD 交接 | 需求评审阶段按需：F2 核心 PRD | 按本轮模块完整说明，引用当前原型与规则 |
| 先定跨页面行为 | 按需：公共规则 | RULE-xx 规则表与影响范围 |
| 先理清页面和去向 | 按需：功能流程与页面状态 | 同一份流程与页面清单 |
| 准备交给原型工具制作 | 按需：原型制作交接 | 制作清单与旁注草稿，外部执行保持待同步 |
| 已收到初审或终审意见 | 按需：评审修改 | 意见影响矩阵与本轮可替换正文 |
| 送终审或需求评审前检查 | 按需：全局一致性检查 | 当前资料之间的冲突、依据及待同步内容 |
| 需求评审时给研发测试用例 | 按需：产品验收用例 | 模块分组的三列表预期用例 |

完整埋点方案和 F3 开发实测清单均为可选。工作台中的“确认交付物”表示把该版本作为后续生成依据，不代替公司初审、终审或研发需求评审。

### 先找竞品，再采集与分析

地区可选「全球（多市场合并）」：使用美国、英国、德国、日本、印度、印度尼西亚、巴西、沙特八个常用市场，不是全量全球或全球排名。页面显示实际成功/失败市场，候选保留具体详情市场；采集前可以调整国家，并查看预计评论上限和翻译提示。

每张候选卡还有「查看收入来源／补充」。先复制应用 ID，到 Sensor Tower、AppTweak 或 AppMagic 核对；查到后可记录金额/区间、币种、周期、地区、广告或商店收入类型、净毛口径与来源链接，保存为项目资料。当前未自动接入收入数值，未获取不等于零，人工记录也不等于已经核验。来源的全球收入与八个商店市场合并不是同一口径。

在资料页输入品类／功能关键词、平台和国家，候选卡片显示可获得的商店信息，可筛选或排序本次结果。搜索顺序不代表市场排名，安装区间不代表近期下载量或收入。缺字段不补造；需要更多信息时展开读取描述和截图。搜索阶段不抓评论、不调用模型，也不自动选取竞品。

勾选后，逐个指定参考用途与简短备注，点击「采集所选竞品」调整评论和市场范围。发现市场与实际采集市场分开记录。采集结果仍是待确认资料，预览截图及原文／译文评论样本后再确认；可以显式批量确认当前范围内已就绪的结果。确认后的资料可直接带入 F1 首章准备表单，核对资料后再开始生成。

F1 确认一章后可继续下一章，不必返回任务列表重新寻找入口；仍保留逐章检查和最后合并。上游改稿时，后章出现复核提示；只有你明确复核并再次确认才消除本轮提醒，不自动改动下游正文。

## 输入什么

- 产品名称和方向；
- 可选目标平台（Android、iOS 或双平台）；
- 指定竞品；
- 竞品评论 CSV；
- 政策来源；
- 技术日志；
- 竞品或现有产品截图；
- 已有研究资料、PRD 或其他文档。

也可以在「资料」页直接采集已知竞品，或先用「找竞品」搜索后手选。采集结果先暂存，预览确认后才把标准评论 CSV、商店描述与截图写入当前项目；工作台会用 UTF-8/ASCII 安全协议处理 Windows 子进程，因此评论中的 emoji、中文等字符不会因 GBK 控制台编码导致采集失败。空结果或失败不会伪装成成功资料。

支持 MD、TXT、CSV、JSON、文本 PDF、DOCX、PNG、JPG、JPEG、WEBP。扫描 PDF 需要先 OCR。

工作台使用双索引 Hybrid RAG：当前项目上传资料和已确认交付物进入项目隔离索引，Product KB 中 active 的方法、模板和案例作为全局补充。检索结果保留来源与原文供人工核对；索引或模型不可用时自动回退关键词，不影响继续准备任务。

## F1 新品需求分析

F1 不是一页定义卡，而是恢复到 Heart Rate 新品分析的完整产品结构：

1. 文档信息与核心结论；
2. 项目背景与资料索引；
3. 行业与市场背景；
4. 用户分层、场景和需求；
5. 用户提供候选的选用依据，以及已选对标的功能、评论、页面和商业化差异；
6. 产品定位、价值主张、首次价值和再次使用；
7. V0 现在做、后置和不做；
8. 产品功能框架；
9. 当前首版实际需要的核心模块方案，不为数量套用标准 App 结构；
10. 启动、核心任务、再次使用和商业化流程；
11. 商业化策略；
12. 本轮下一步交接，可进入原型某模块、必要体验补查或按需 PRD。

F1 不生成平台、权限、数据或政策独立章节。具体页面确实依赖权限时，放到 F2 对应页面说明，不在新品分析中展开。

新建 F1 时，系统自动检索只把用户输入和当前项目上传资料作为当前项目证据；历史 F1、旧 PRD 和其他已确认交付物不会自动带入，避免旧文档中的推测污染新的新品分析。需要参考旧文档时，在任务准备页手动勾选并核对其来源。

目标用户根据竞品场景和资料描述，不以访谈为前置，也不硬凑核心/次级画像或无依据的留存、付费原因。所有勾选资料进入资料索引并支持相关结论，不复制整份 CSV、日志或研究资料。用户输入和当前项目资料支持事实，案例与模板只提供方法；没有覆盖的内容直接说明。篇幅按各章任务预算控制，没有最低字数，不为填满目录扩写。首版范围在第 6 章详细维护一次，后续只引用或补变化。

竞品章按已有候选记录近期下载与累计安装、收入覆盖、实际体验、选用角色及来源口径。缺数据不写 0，商店收入不代表广告收入，口径不可比时不强排。最终选用由你决定；已选好则直接拆解，不重新筛选，也不强迫每款查全。单竞品用“观察 → 产品含义 → 本产品取舍”短条目，只有相关问题才深入。

## F2 核心 PRD

F2 是需求评审阶段按需维护的独立核心 PRD，不是原型阶段的“原型与需求旁注交接”任务。按本轮实际范围与模块整理当前原型，不再将完整项目硬压成 3–5 页或 8,000 字：

- 当前原型、实际读取范围与本轮包含内容；
- 模块流程、中文页面名和稳定 ID，区分页面、弹窗、局部状态和系统说明；
- 先写页面用途、呈现形式、背景、区域位置层级、默认状态与完整 UI 文案，再按业务主题写条件、操作、结果及必要返回恢复；
- 跨页共享规则集中维护，页面引用 RULE-xx；
- 必要英文 UI copy；
- 按模块集中说明参考竞品/截图与差异，页面只有新的取舍才补充；
- 资源需求、具体待决定项和受影响产物的同步位置。

页面说明按业务分组，不固定套用四栏目。旁注与 F2 共用一份已确认页面正文和稳定 ID：已有说明直接沿用，局部任务只补授权变化；完整 PRD 则汇入同一份正文并合并确认变化，不自由重写另一套。已有流程索引只列变化；简单状态补差异，复杂页面才需要独立文案核对表。没有可读原型时说明缺口，不能把制作建议写成已看到的布局。F1 背景只引用，不重复。

规则变化按“旧口径 → 当前已确认新口径 → 各产物具体页面或章节”核对，同轮变更表只维护一份，其余引用 REV/RULE。实际画面或实现与约定不同时列出差异，不能把新草图或实现偏差自动当成新决定。未读到的位置标未核对，未实际写回的对象标待同步；生成替换正文不等于全局修改完成。

原型交接任务目前输出制作说明与旁注草稿。工作台不会因为生成文档就自动修改 Figma 或 Axure；实际写入、回读、截图查看和真机测试分别记录，未执行内容保留“待同步 / 待验证”。

## 产品验收用例（按需）

需求评审前可以根据当前原型、F2、流程和公共规则生成三列表用例：

| 验收场景 | 操作步骤 | 预期结果 |
|---|---|---|
| 稳定用例 ID＋场景中文名 | 前置条件与可执行操作 | 可判断的界面、数据、权益与返回结果 |

按模块分组，只写预期，不混入实测状态或通过结果。旧验收文件只是参考，须与当前规则对照后再用。

## F3 开发验收清单（可选实测）

已有三列表产品验收用例时，沿用原编号、场景、步骤和预期；有构建和实际测试证据后只补：

- 实测结果和状态；
- 日志、截图、录像或测试报告；
- 问题、负责人和修改结果；
- 复测证据；
- 本轮实测结论和仍未执行的范围。

埋点验证按需引用完整方案或公共 SDK 原事件 ID、参数及触发口径，不重新设计、不按固定数量截断。实际日志、状态和复测统一在 F3 维护；埋点设计文档只保留验证映射。没有实测证据仍为 NOT_RUN，不为进入下一阶段预填通过。任务预算最多 5,000 个中文字符，大范围可分模块记录，不能以预算删改已确认预期。

## 完整埋点方案（可选）

当需要给研发一份正式事件表时，可直接选择「完整埋点方案（可选）」。输入可以是已确认 F2、蓝湖原型快照、截图或交互资料，不强制先补独立 PRD。已有工作簿时保留 Sheet、列、公式、事件名和公共预设；没有可识别页面与交互时只说明资料缺口，不造事件。需要使用蓝湖时，先到「能力与工具」页的 Lanhu MCP 卡片点击「配置 / 重新检测」；默认读取本机 Codex 配置，也可以指定配置文件路径。

- 有蓝湖原型时，先由当前会话通过 Lanhu MCP 只读读取页面、状态和弹窗，再将脱敏快照作为项目资料导入；工作台不保存 Cookie 或 Token；
- 没有蓝湖时，可以直接勾选 F2、截图或已有交互文档；
- 方案覆盖页面展示、普通点击、选择、异步结果、权限、失败/取消/超时、核心漏斗和研发验收映射；
- 事件 ID、参数名和枚举值使用英文，说明使用中文；不得记录精确位置、设备地址、原始用户内容或其他可识别信息；
- 当前工作台先交付结构化中文 Markdown，并可直接导出 Word、PDF、Excel 和 CSV；导出不调用模型改写正文。

蓝湖快照的导入必须基于当前账号已有权限。链接不可访问时，不根据页面名称猜测原型内容，应改用截图或 PRD 资料。

## 怎么运行

1. 打开 `http://127.0.0.1:8765`；
2. 新建或进入项目；
3. 上传资料；
4. 选择当前阶段的任务；F1 五章保留分步生成，已有原型或意见时直接进入对应任务；
5. 勾选最多 12 份要写进文档的资料；
6. 生成并检查任务包；
7. 开始生成；
8. 如果要指定位置修改，把鼠标移到正文的章节、段落或表格旁，点击「添加批注」；
9. 选择新增、修改、删除、压缩或保留，填写具体意见；
10. 点击「按 N 条批注精确修订」，生成带父任务和来源版本的新修订任务；小改也可以直接编辑 Markdown 并保存为新版本；
11. 修订版成功生成后，参与修订的批注会自动标记解决；检查新版后再确认，供下一份交付物引用。任务完成与文档确认不表示部门业务评审通过。

交付物详情页还会显示轻量质量校验。只有确定性硬错误会阻止确认，提示项只供修改参考；F1 如果出现没有来源编号的市场、用户或竞品数字，会显示证据提醒。项目页或资料页可以导出完整 ZIP 项目包；侧栏「导入项目包」会创建一个新的项目副本，不覆盖现有项目。

## 怎么修改已经生成的交付物

生成结果后有三种修改方式：

- 小范围调整：点击「编辑正文」，直接修改正文。每次保存都会生成 V2、V3 等新版本；
- 指定位置让模型修改：在对应章节、段落、引用、表格或代码块旁添加批注，再点击「按 N 条批注精确修订」；
- 整份文档需要重写：填写「整份文档评审」，记录整体修改意见，再点击「按意见准备修订版」。

定位批注会绑定创建时的文档版本。每条批注包含位置、原文、修改动作、意见、提出人和处理状态；旧版本批注不会驱动当前版本修订。批注本身不进入交付物正文。只有修订任务成功生成完整新版后，参与该次修订的批注才会自动标记解决；生成失败不会改变批注。

当前版本还有待处理批注，或正文引用了任务快照中不存在的 `[Sx]` 时，工作台会阻止确认。可选 F3 实测清单的结果仍为 `Conditional` 时，需要继续在同一份清单补充修改和复测，变为通过后再确认。三列表“产品验收用例”只定义预期，不要求伪造实测结果才能使用。

### 规则变更后怎么同步

采用“当前用户确认 → 当前实际材料或行为 → 已接受项目文档 → 历史记录 → 通用模板”的顺序判断。当前确认与实际原型或实现不一致时，明确列出差异，不把确认意图当成已经落地。

改动公共规则时先列出影响范围，再更新规则、画面与旁注、需求、流程和验收预期，最后查找旧口径。工作台的“评审修改”会给出修改内容与同步位置；没有实际操作的外部原型及其他文件仍须保留待同步。送终审前使用“全局一致性检查”对照当前材料；文件名叫“正式”或“最终版”不能替代内容核对。

点击「版本记录」可查看旧版，并将任意旧版恢复为新的当前版本。恢复不会删除中间版本。已确认文档发生编辑或恢复后，会自动回到待评审状态，避免未经复核的新内容直接成为后续任务依据。

### 在正文中插入图片

先在「资料」页上传 PNG、JPG、JPEG 或 WEBP；截图后可连续按 `Ctrl+V` 暂存多张图片，确认后一次上传。编辑正文时，在光标处选择图片并点击「插入到光标处」，工作台会写入 `![图片说明](asset://图片ID)`。图片只属于当前项目，预览、Word/PDF 导出、版本恢复和项目包迁移都会保留引用；引用不存在的图片不能保存。资料目录可以删除未被正文、历史版本或任务引用的图片，被引用的图片会被阻止删除。

### 导出或迁移项目

项目页或资料页点击「导出完整项目」得到 `workbench-project-v1` ZIP，其中包括项目背景、资料、图片、任务包、交付物、版本、批注、评审和评论采集记录。导入时系统会校验路径和 SHA-256，并为项目、资料、任务和图片生成新的 ID；不会覆盖原项目，也不携带 Codex/Lanhu 凭证、Cookie、Token 或向量索引。

## 怎么删除项目

进入「项目背景」，在页面底部点击「删除这个项目」，输入完整项目名称后确认。系统会阻止删除仍有生成任务运行或排队的项目。

删除前会自动保存完整本地备份，包括项目背景、原始资料、任务记录、交付物、全部版本和批注。备份位于 `workbench/data/trash/<时间>-<项目ID>/`。删除后项目不再出现在工作台，可从侧栏「项目回收站」恢复。永久删除回收备份时需要再次输入完整项目名称，且之后无法恢复。

## 怎么整理任务记录

- 默认只显示每条修订分支的最新版；
- 可以切换到全部、需要处理、已确认、待执行、待评审或已归档；
- 任务详情会显示生成时使用的快速/完整模式；切换项目模式不会改写历史任务；
- 归档任务只影响列表展示，不会删除任务包、来源快照或交付物；
- 已取消、执行失败或服务重启中断的任务都可以恢复为待执行。

## 什么时候使用完整模式

只有明确需要历史 0–12 章、正式投资评审或大型跨团队研究包时才使用正式 T1–T4。普通的“完整新品分析”使用现在的 F1；它已经包含 Heart Rate 式完整产品分析，只是不增加风险、假设验证、Spike 和 Gate。

## 不包含

- 付费投放和媒体采买；
- 投放归因；
- ASO 文案和商店素材；
- Google Play / App Store 发布执行；
- 默认用户访谈计划；
- 默认技术 Spike 和风险管理流程。
