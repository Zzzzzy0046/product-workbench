# Codex 连接与首次使用

适用版本：产品工作台 Windows `2026.10.22.4` 起。每位使用者连接自己电脑上的 Codex，不需要工作台账号，不使用原作者的登录凭据。

## 同事收到 ZIP 后怎么做

1. 解压 ZIP，双击 `ProductWorkbench.exe`，保留控制台窗口。
2. 浏览器中打开左下角「能力与工具」，查看顶部「连接你的 Codex」卡片。
3. 点「检测 CLI / 登录状态」。这一步只运行本机 CLI 版本检查与登录状态检查，不调用生成模型。
4. 已找到且已登录时，可以直接继续使用。未登录时点「使用浏览器登录」，确认后由本人在官方浏览器页面完成授权。不要把账号、密码、Key 或认证文件发给别人。
5. 如需验证账号、模型与网络是否真的可用，单独点「连接测试」并确认额度提示。它只发固定极小请求，不包含项目背景、评论、截图或其他业务资料。
6. 测试通过后回到项目，选择资料、准备任务包，再由本人点击「开始生成」。

登录可能更新该电脑上共享的 Codex 登录状态。工作台不会提供登出按钮，也不会自动登出、自动登录、静默安装 CLI 或在打开页面时自动消耗模型额度。

## 找不到 CLI 怎么办

展开「CLI 路径与运行信息」。可从发现的原生 CLI 中选择，也可粘贴该电脑已有的完整 `codex.exe` 路径，然后保存。路径配置只保存在当前本机工作台数据中，不进入项目包。

- 手动路径仅接受本机真实的原生 `codex.exe`，不接受脚本、命令参数、网络共享或认证文件。
- 自动发现包括已有环境变量、系统 PATH、npm 安装入口，以及受限的常见 Codex 桌面安装目录；不会全盘搜索个人文件。
- 使用 npm 自动入口时不用把 `codex.js` 填进 EXE 路径框，保持自动检测即可；该入口仍需要本机 Node.js。
- 如果 CLI 由 `WORKBENCH_CODEX_BIN` / `WORKBENCH_CODEX_JS` 启动环境强制指定，应先调整该环境。页面不能覆盖它。
- 仅安装了桌面 App，不等于 CLI、登录和生成都已经验证。安装位置或账号缓存不兼容时，应按官方 CLI 指引检查。

## 三种状态不要混淆

| 状态 | 能说明什么 | 还不能说明什么 |
|---|---|---|
| 找到 CLI | 本机有可调用的入口 | 账号是否登录、网络或模型是否可用 |
| 已登录 | CLI 报告存在登录状态 | 额度、模型权限和实际请求是否成功 |
| 生成测试通过 | 当次固定小请求成功返回 | 其他模型、长文档、未来网络或设备操作也一定成功 |

检查、登录和测试分别记录状态。变更 CLI 路径、模型或连接配置后，旧的验证状态会失效。登录状态也可能被其他 Codex 客户端改变，需要时点击检测更新。

## 等待、取消与故障

- 登录时保留工作台页面，在这台电脑弹出的浏览器中自行授权。超时或失败后可以重试。
- 「取消本次操作」只停止工作台启动的该次连接操作，不登出账号，也不按进程名关闭其他 Codex。
- 工作台正在生成文档或走查时，不允许改 CLI 路径、登录或运行连接测试；连接登录或测试进行中，也不能开始新的生成或走查。
- 网络、额度、模型和 CLI 版本问题会显示分类提示，不在页面输出原始 CLI 登录文本、OAuth 链接或认证值。
- 登录成功但生成失败，先检查提示中的网络、额度、模型权限或 CLI 版本。反复登录不一定能解决这些问题。

## 凭据与项目数据

工作台不直接读取、复制或导出 `auth.json`，也不采集浏览器登录输入。认证缓存仍由 Codex CLI 及系统凭据存储管理。项目导入导出不会携带本机 CLI 路径配置、认证文件、连接操作日志或模型测试临时文件。

官方登录及缓存说明：[Codex 认证](https://learn.chatgpt.com/docs/auth)。命令说明：[Codex login](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-login)。实际安装方式和账号可用性以官方当前说明为准。
