# 完整工作流的范围边界

日常工作按“市场与竞品分析 → 原型图＋需求说明 → 初审修改 → 终审整理 → 需求评审”从当前阶段继续。F1 保留完整新品分析；独立 PRD、完整埋点和开发实测按需，不要求重复建立已有旁注、公共规则、流程或用例。

没有真实构建和测试证据，不填写验收通过。只有项目已经存在真实产品数据时，才按需进入产品指标、留存、商业化表现和版本迭代诊断。正式研究、预研和阶段控制仅在明确要求时展开。

本轮目标与评价方式以用户当前输入为准，不默认附加固定回收周期、收益目标或放行门槛；用户明确提供的相关指标仍可作为项目资料使用。不批量改写已有项目背景、上传原文或历史交付物。

明确排除：付费获客、媒体采买、投放归因、ASO 文案、商店素材、Google Play/App Store 上架、灰度发布、版本发布和商店回滚。

快速 F1 不输出平台、权限、数据或政策章节。只有具体 PRD 页面或验收项确实依赖系统权限时，才在对应功能中写必要规则；完整研究模式仍可按明确要求进行专项政策检查。
