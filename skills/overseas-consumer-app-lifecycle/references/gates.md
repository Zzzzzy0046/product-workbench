# Formal gate definitions

The fast path does not use Gates or condition closure. Read and apply this file only when the user explicitly requests a formal stage review, an opportunity decision, or the historical full workflow.

## G1 Opportunity Gate

Use only when the user asks whether an idea is worth doing or wants to screen multiple ideas. It is never a default blocker for an assigned category.

## G2 Definition Gate

For formal work, confirm that current competitor/user evidence has been translated into positioning, differentiation, bounded scope, platform decision and a no-build list.

## G3 Solution Gate

For formal work, confirm that the main flow, relevant states, business rules, permissions, privacy, dependencies and acceptance criteria are reviewable.

## G4 Development Acceptance Gate

Use actual build/device behaviour, logs, screenshots, tracking output and retest evidence. A plan or static document cannot prove implementation acceptance.

## G5 Iteration Gate

Use only when real product data exists. Diagnose activation, retention, monetisation, quality and guardrails before deciding Continue, Iterate, Hold or Retire.

## Formal decision record

When a formal Gate is explicitly requested, record outcome, rationale, source evidence, unresolved items, owner, due date and next action. These fields do not apply to the default fast path.
