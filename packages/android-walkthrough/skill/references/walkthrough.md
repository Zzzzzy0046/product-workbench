# 采集协议与恢复

## 一次 observe 做了什么

1. 查前台窗口（`mCurrentFocus`，按机型自动选 `dumpsys window displays/windows`，选中的写法缓存进 `aw.json`）。
2. 自动清场（见 ads.md）。前台不是目标 App → `NOT_TARGET_APP`，不登记。
3. **截图与 UI dump 并行**。只有出现"小而方"的转圈 ProgressBar 才判为加载中，短轮询最多 `--settle` 秒；横条进度条（播放进度、步骤条、额度条）不算加载。
4. 再查一次前台，变化则 `FOREGROUND_CHANGED`，不登记。
5. 保存 `observations/<id>.png / .xml / .json / .view.jpg`，更新 `capture-session.json`。

正常页面约 4 次 ADB 调用。UI dump 失败（持续动画、游戏、视频、地图）时 `status: visual_only`：截图保留，可 `tap-xy / back / swipe`，不能按序号点。

## 一次 act 做了什么

1. 只接受最新观察；应用/设备必须一致。
2. 清场 + 前台核对：有广告被关闭（`AD_CLEARED`）或前台变了（`FOREGROUND_CHANGED`）→ 不执行，**直接附带新观察返回**。
3. tap/text/tap-xy 始终重新 dump，核对可操作控件结构，以及将操作目标的子树文字/id、类型、位置、焦点和密码属性；变化 → `UI_CHANGED` + 新观察，不发送输入。不会因为观察不足 8 秒而跳过；`--fresh` 只兼容旧参数。无关控件的倒计时/轮播文案不阻塞当前目标。
4. 使用当前目标的 guard 拦截购买/订阅/试用/安装/密码控件。坐标命中已有控件时使用该点最具体的可操作控件；无 UI 树的 `visual_only` 仍可按最新截图受控点坐标，但出现新的可操作控件时先返回新观察。
5. 先把断点标成"动作待确认"，再发送输入；等待 `--wait` 秒后观察。观察失败时错误带 `acted: true`，下次 observe 会把这个动作记为 `unresolved_action`，**不会**被连成箭头。

## 地图规则

- 一个观察最多登记成一个状态；状态 id 不可覆盖，新画面用新 id。
- 箭头只在"目标观察的上一步 = 源状态的观察"时成立，动作直接复制采集记录，不能手写。`map edge` 仅用于事后补连这种相邻关系。
- `map state --obs <id> --as auto --page P0x` 可把较早的观察补登记成状态（例如当时忘了加 `--as`）。
- 中间未登记的观察会作为祖先自动写入地图摘要，但不分配页面、不连箭头。
- 地图只存观察摘要；完整控件树在 `observations/*.json`，需要时 `--full` 或直接读文件。

## 恢复

- 断开、超时、`acted: true`：先 `observe` 看当前位置，再决定；不要重发上一动作。
- 中断后续跑：同一个 `--out` 直接 `observe` 即可，旧序号全部作废。
- `DEVICE_LOCKED`：同一设备已有命令持有 OS 文件锁，等待其结束。锁持续持有到操作退出，进程被强制结束后由 OS 释放；锁文件可以保留，不按 PID/文件年龄回收，也不要手动删除它。
- 动画 restore 成功后清除本轮备份；无备份时不写设置，重复恢复不会把原值改成默认 1。恢复中途失败会保留备份，便于重试。
- 换 App 版本做大改动对比：用新的 `--out`，不要混进旧地图。

## 耗时口径

`timings.jsonl` 每行一条命令：总秒数、ADB 调用数和分阶段耗时。它不含命令之间模型思考和人工处理的时间。比较优化效果须同 App 版本、同设备、同路径。
