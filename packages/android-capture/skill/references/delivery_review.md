# 交付前审查机制

用于检查按模块流程拼接的 PNG、模块地图和原始截图；product_summary.md、Word 只在本轮请求生成时检查，不因审查扩大交付范围。不再默认输出 Axure 模板或网页。

目标不是写更长的报告，而是确保交付物可以支撑产品判断，不会出现“截图很多但证据不完整”的问题。

## 审查顺序

1. 先跑结构化验证脚本 `scripts/review_delivery.py`。
2. 再按本文做人工审查。
3. 修复明显缺口后，再给用户最终回复。

## 结构完整性

先核对本轮选定模块和问题。以下是完整走查的候选范围，不是 quick 的强制清单：

- 启动页 / 首启状态。
- 语言、地区、onboarding。
- 权限弹窗。
- 首页和主导航。
- 每个主 tab。
- 核心任务路径。
- 任务完成后的结果页。
- 设置 / account / legal。
- paywall / subscription / IAP。
- 评分弹窗。
- 广告触点。
- 空状态 / 错误态 / 阻断态。

如果所选路径没走到，要写明原因，例如：需要登录、需要订阅、需要外部账号、广告阻断、设备权限不足、页面无法识别。未选择路径不补采凑全。

地图模式额外核对：

- research-map.json 的包名/serial 与 observation 一致；截图、XML、JSON 路径与归属可追溯。
- 页面属于主要业务模块；不同状态挂在对应页下，不把 UI 控件树当业务模块树。
- 跳转的前后观察和动作匹配，不因两张截图相邻就连边。
- complete 有实际所选路径与覆盖说明；partial/blocked/skipped 不隐藏。
- 文件有效、脚本 PASS、路径完成是不同结论。脚本不能代替人工判断覆盖是否足够。

## 证据一致性

若生成 product_summary.md，检查：

- 每个重要结论是否有截图支撑。
- 每个主要章节是否引用了对应截图。
- 截图文件是否存在。
- 截图文件名是否和页面内容一致。
- 是否把观察到但没截图的内容标成“观察到，未单独保留截图”。
- 是否避免用截图无法支持的过度判断。

若本轮请求 Word，检查 product_summary.docx：

- 是否已经从同一份 `product_summary.md` 导出。
- 是否是便于评审的精简版，而不是把完整 MD 原样搬进去。
- 订阅、广告、评分、paywall 的关键判断是否已汇总到“总体判断”。
- “总体判断”是否写清订阅出现时机、价格、试用期、CTA 和主要权益。
- 弹窗出现时机表是否保留在 Word 中，并导出为真实 Word 表格。
- 完整截图流水账是否留在 MD 中，而不是默认塞进 Word。
- Word 内是否能直接看到主要截图，而不是只有本地图片链接。
- 图片是否按章节嵌入，大小适合阅读和复制。
- Markdown 表格是否已经转成真实 Word 表格，不要残留 `|---|` 或 `| 类型 |` 这种源码格式。
- 请求的 Word 没有生成时说明原因；未请求则无需生成或列作缺失。

脚本默认会优先读取 research-map.json；地图模式不强制 Word 和 summary。当前交付使用 `--require-flow` 检查流程拼图；按需可用 `--require-summary`、`--require-docx`。research_map.py check 的缺文件警告不能当最终交付成功；review_delivery.py 会把丢失证据列为错误。

## 商业化完整性

所选路径涉及商业化时，检查实际观察内容是否记录：

- 首启 paywall。
- 功能入口 paywall。
- 完成任务后 paywall。
- 订阅价格、试用期、CTA、权益文案。
- Remove Ads / Pro / VIP 等入口。
- 评分弹窗出现时机。
- 广告类型、出现时机、是否外跳、是否可关闭。

## 双设备完整性

双设备模式额外检查：

- serial / model / role map 是否写清楚。
- 两端是否分别截图。
- 邀请码、二维码、分享链接、配对码是否有来源端截图。
- 接收端输入/扫码是否有截图。
- 两端成功/失败状态是否都验证。
- 是否记录只有一端成功的 UX 不一致。
- 是否避免在报告中暴露精确位置、联系人、账号等隐私。

## 流程拼图完整性

检查 flow_export：

- 是否有各模块的 `*_flow.png` 和 flow_notes.md。
- 是否以截图为主体，按 research-map.json 的真实跳转排序，没有套左文右图的 Axure 说明模板。
- 箭头是否对应真实的源状态、动作和目标状态；没有跳转的截图是否明确单列，而不是按采集时间连线。
- 分支、回环和跨模块跳转是否清楚；长流程是否合理分页。
- 未采集模块是否明确显示缺口，绝不使用其他模块或全局截图补位。
- 页面名、操作文字是否可读，截图是否保持比例。
- 至少抽查一个正常流程图和一个分支/缺图流程图。
- 是否没有把旧 flow_export、axure_export 当原始截图再次拼接。

旧 `--require-axure` 仅为历史兼容；当前任务不调用旧模板，也不把没生成 Axure 文件当缺失。

## 隐私和安全

最终文字和分享材料不要暴露：

- 精确地址、门牌、地图坐标。
- 联系人、手机号、邮箱。
- 账号、token、验证码。
- 支付信息。
- 私人相册或文件名中的敏感内容。

如果截图含敏感信息，原始截图仅留本地；分享的流程拼图、Word 等必须先脱敏，不能只在正文隐去而仍把敏感像素嵌入交付物。

## 最终回复必须包含

- 截图目录。
- 截图数量或主要分组。
- 各模块流程 PNG 的链接、已覆盖模块及未完成原因；地图路径作为追溯信息。
- 如果本轮请求 summary/Word，说明是否生成及路径；没有请求不为此扩写报告。
- 流程拼图目录 flow_export；不需要在 Axure 打开，不宣称为可点击原型。
- 已验证的内容。
- 仍可能遗漏或被阻断的路径。
- 如果广告阻断过流程，说明广告触发点和处理结果。
