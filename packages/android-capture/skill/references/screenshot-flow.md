# 按模块流程拼接截图

目标很简单：截图后按模块和实际操作顺序拼成图片。截图是主体，只配页面/状态名、操作文字和箭头。不套 Axure 的左右说明模板，不开发网页，不要求用户先读地图文档。

## 拼图规则

- 按业务模块输出，一模块可有多张图；只排列本轮真实采集的页面与状态。
- 箭头来自 research-map.json 中已校验的 transitions，箭头文字使用简短操作，如“点击导入”“返回”。不按截图文件顺序猜流程。
- 无分支短流程连续横排，每行最多三张；分支分别成行，返回同页或跨模块跳转标清页面/状态编号与模块。返回同页的新观察使用新的状态编号，但不新增一个同用途页面；同一张截图可为说明不同真实路径重复出现，不将重复视为新页面。
- 只有截图、没有跳转证据的状态单列“未关联流程”，不能为了好看自动补线。
- 截图保持原始比例；页面名、操作名过长时换行。模块过长分页，不压成看不清的超宽小图，不枚举所有组合路径。
- 缺图用明确占位，未采集模块写明未采集/阻塞，不从别的模块取图填充。
- 原始 PNG/XML/JSON 不移动、不改名；拼图是派生副本。

## 生成

截图和地图已登记后，运行：

```powershell
$PY = "<可用 python.exe>"
$OUT = "<采集目录>"
$F = "C:\Users\simon\.codex\skills\android-app-screenshot\scripts\build_flow_montages.py"
& $PY $F --input-dir $OUT --title "<App 名称>"
& $PY "C:\Users\simon\.codex\skills\android-app-screenshot\scripts\review_delivery.py" --input-dir $OUT --require-flow
```

依赖 Pillow，优先使用当前项目已具备依赖的 Python。默认读取采集目录的 research-map.json，输出到 flow_export/。可用 --research-map 指定地图、--out-dir 指定输出目录、--rows-per-image 控制每图行数。指定目录仍要保留对原始研究目录的路径边界，不读取目录外截图。

输出包括各模块的 `*_flow.png` 和 flow_notes.md（图文件、原始截图引用及缺口）。用户直接打开 PNG 就能看，不需要 Axure。地图和笔记只用于追溯与续跑，不代替图片。

## 验证与回复

人工至少打开一个正常流程图和一个有分支/缺图的图，核对箭头源和目标、操作文字、截图比例、分页和长文本是否清楚。自动文件检查通过不等于流程正确或模块覆盖完成。

最终回复先给流程 PNG 的链接和模块列表，再说明缺口。没有实机采集就标明合成示例，不能把测试图当竞品事实。用户未要求时不另外生成 Word、网页或 Axure 拼板。
