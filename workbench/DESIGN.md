# 工作台设计与扩展边界

## 要解决的问题

产品工作被多个文档和对话拆散。工作台保存项目背景、当前目标、证据与交付历史，使下一次任务有明确起点；单次只完成用户选择的交付物。

## 参考理念如何落地

参考仓库：[hy459229090-lang/ai-pm-workflow](https://github.com/hy459229090-lang/ai-pm-workflow)，核验版本 `03a6a255b037fd0cb943130c145042eccc8ea0a1`。

采用的是理念映射，没有复制其业务代码；仓库中的效率比例属于作者论述，不作为本项目验收指标。

用户已确定要做的品类不设机会门。评审用于管理交付物是否可作为后续依据，不强制拦住所有其他任务。投放执行与商店发布不进入范围。

## 实现结构

```text
浏览器：项目 / 背景 / 资料 / 任务 / 交付物 / 能力库
    ↓ 本机 HTTP JSON
app.py
    ├─ 项目与任务存储 → SQLite
    ├─ 文档解析 → 原文件 + 文本
    ├─ 任务注册 → capabilities/*.json → Markdown 模板
    ├─ 上下文装配 → 项目背景 + 当前工作 + 本次要求
    ├─ 证据检索 → 当前项目已确认资料 + active 知识
    ├─ 执行器 → 已登录的本机 Codex CLI
    └─ 评审与修订 → 版本记录 + Markdown 输出
```

## 扩展点

任务扩展是当前可直接使用的配置能力。工具扩展预留为后端适配器；不能把工具名称存在列表里等同于已经接入工具。模型目前只有 Codex 适配器；文档目前只输出 Markdown。

检索先使用不依赖模型下载的中文双字/英文关键词切块搜索。后续可把检索函数换成项目级 Hybrid Index，但必须保持项目隔离、来源快照及未确认稿排除规则。

## 后续优先级

1. 用一份实际资料完成一次真实工作，检查引用覆盖和产物可用性。
2. 根据真实缺口接上桌面评论采集器及 Hybrid 检索，处理采集失败、限流、数据完整性。
3. 按实际交接需要增加 Word / Excel / 原型导出。

账号、多人协作、多 Agent 调度与自动全局知识发布暂不纳入当前版本。
