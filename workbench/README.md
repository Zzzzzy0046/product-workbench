# 本地产品工作台

V1.1 面向小型出海 App 团队。用户给出的新品默认就是要做，工作台提供四个可独立进入的日常工作流：新品开发、版本迭代、竞品分析和版本复盘。

```text
市场和竞品分析（F1 五章分步生成）
  → 原型制作交接＋中文需求旁注（按模块；外部工具制作原型）
  → 初审修改
  → 终审整理
  → 需求评审
```

从当前阶段进入，每轮只生成需要的内容；各阶段业务结论由实际评审人确认。公共规则、功能流程与页面状态、原型制作交接、评审修改、全局一致性检查和三列表产品验收用例按需调用。新品主线中，独立 F2 PRD、完整埋点与 F3 开发实测清单为可选，不再默认串成必跑全套；版本迭代预设仍包含 PRD 与开发实测任务。

版本迭代可按需增加产品基线、版本简报和版本复盘；这些不会被强塞进新品开发主路径。产品版本也是可选归类：不创建版本可以直接做产品级任务，创建后则把本轮资料、评论、任务和交付物组织在一起。

项目与版本的目标按你本轮输入整理，不默认附加固定回收周期、收益目标或放行门槛。你明确提供的经营指标可以继续使用；已有背景、上传资料与历史交付物不会被自动改写。

竞品评论 CSV、政策来源、技术日志、截图和研究资料作为证据附件进入资料索引，相关结论引用它们；不把整份原始数据复制进主文档。F1 只把用户输入和当前项目资料当作产品事实依据，Product KB 的历史案例和其他产品文档只用于结构参考；资料没有覆盖的内容明确写“当前资料未覆盖”，不为凑篇幅补写。快速模式不生成用户访谈、假设验证、风险清单、技术 Spike、Gate 或条件闭环。

## 代码结构

工作台保持单机、单进程和原有 SQLite，不引入微服务或前端构建工具；迭代 3–4 只把职责拆清楚：

```text
workbench/
  app.py                    # 启动、依赖组装、Workbench 兼容入口
  core/                     # 常量、文本、文件安全、运行配置
  services/                 # 项目、产品版本、工作流、资料、检索、任务、导出、校验、存储
  adapters/                 # Codex、Lanhu、竞品评论采集
  api/                      # Handler、路由映射、响应序列化
  static/
    app.js                  # 前端启动与轮询
    modules/                # 状态、API、通用函数、Markdown、事件
    render/                 # 工作区渲染
    features/               # 项目、产品版本、资料、任务、交付物和集成操作
```

原 HTTP API、数据库表和 `Workbench` 方法继续兼容。后续代码调整按 [行为基线](../docs/WORKBENCH-BEHAVIOR-BASELINE.md) 回归；模块化实施状态见 [重构清单](../docs/WORKBENCH-MODULAR-REFACTOR-CHECKLIST.md)。

## 启动

在仓库根目录运行：

```powershell
.venv\Scripts\python.exe workbench\app.py
```

打开 **http://127.0.0.1:8765**。也可以运行 `workbench/start.ps1`。模型生成需要联网且本机 Codex 已登录。

Codex 入口优先使用 `WORKBENCH_CODEX_BIN` 指定的原生可执行文件，其次为显式 `WORKBENCH_CODEX_JS`、PATH 中的原生 CLI、默认 npm JavaScript 入口。显式路径无效时直接提示，不悄悄切换安装。模型仍读取 `WORKBENCH_MODEL` 或本机 `config.toml`，不会为了兼容旧 CLI 自动换模型。登录凭据不复制到工作台；只在执行时继承连接白名单配置。找到 CLI 不等于真实生成已经通过。

完整流程图、真实连接检查与测试边界见 [整体流程与验证](../docs/WORKBENCH-FLOW-AND-VERIFICATION.md)。

## 使用步骤

1. 新建项目；日常使用「快速迭代」。
2. 在「项目背景」填写产品方向和当前工作；目标平台可从 Android、iOS、双平台中选择，也可以暂不指定。
3. 如果正在做一个明确版本，在「产品版本」创建并切换；新品前期或长期研究可保持“产品级工作”。
4. 在「资料」页导入资料。截图后可以连续按 `Ctrl+V` 加入暂存区，也可以拖入或选择文件；检查预览后点击「一并上传」。支持 MD、TXT、CSV、JSON、文本 PDF、DOCX、PNG、JPG、JPEG、WEBP；每份最大 12 MB，每批最多 30 份。新资料默认关联当前产品版本，并自动归入竞品资料、评论数据、截图与图片、政策与合规、技术与日志、研究资料或其他资料；可在资料卡片上调整分类。图片还会继续归入竞品截图、产品与原型、数据与报表、政策与规则、用户反馈、参考与素材或其他图片。
5. 需要竞品资料时，在「资料」页点击「找竞品」：输入关键词、平台和国家，先查看最多 12 个商店候选，按名称、评分、免费付费或可用安装区间筛选，由你手动勾选最多 8 个并指定主对标／功能参考／变现参考。候选展开时才读取长短描述与截图，不会自动选择、采集评论或调用模型。已有链接时仍可直接采集。进入采集表单后，可调整国家、评论数量、日期、星级、关键词、App 版本、开发者回复、最低点赞数和翻译选项；原文始终保留。采集完成先预览截图与评论样本，再显式确认入库。当前范围已就绪结果支持批量确认；确认后可带入资料直接准备 F1 首章，不会自动开始生成。Android 复用本机 `competitor-analysis-platform` Python 环境，iOS 搜索使用 Apple 搜索接口；搜索可用不等于评论采集环境也已安装。
6. 在「任务」选择新品开发、版本迭代、竞品分析或版本复盘，再进入本轮阶段或按需任务；新品的 F1 保留 5 个章节，从前到后分别生成、编辑和确认。已有原型或评审意见时，可直接进入对应任务。
7. 准备任务时勾选最多 12 份要写进文档的资料。系统自动检索只使用产品级资料和当前版本资料；其他版本资料只有被你显式勾选时才进入。截图会作为图片输入，其他资料会解析为文本。
8. 检查任务包后开始生成；结果先作为待评审草稿。
9. 在交付物预览页，可对具体章节、段落或表格添加批注，也可以直接编辑 Markdown 正文。编辑器可以从已上传图片中插入 `asset://` 图片引用。
10. 交付物页面提供 Markdown、Word、PDF、Excel、CSV 下载；导出只渲染当前版本，不改写正文。
11. 对待处理批注点击「按批注精确修订」；新版生成成功后，本次使用的批注自动标记解决。
12. 确认后，该交付物才会自动进入后续项目检索。确认前会自动显示轻量质量校验；确认表示文档可作为后续依据，不表示公司初审、终审、需求评审或真机验收通过。

F1 每章确认后可直接继续下一章，五章完成后仍由你点击合并。准备表单按项目、产品版本和任务在当前页面内暂存输入，刷新后清除，不保存到浏览器本地存储；其他版本资料默认折叠。前文改稿后，下游旧稿显示“上游已变化”提示，不自动重写或清除原确认；再次确认表示你已复核当前上游，不表示旧正文自动同步。

本轮接入与实跑边界见 [竞品发现与新品链路优化](../docs/WORKBENCH-COMPETITOR-DISCOVERY-UPDATE.md)。

## Android 实机截图走查

在「资料」页点击「实机截图走查」，填写已安装 App 的包名和本轮走查范围，然后开始。只有一台在线设备时自动选中；多台设备需明确选择。首次使用可以在同一窗口配置 `adb.exe`，也可设置 `WORKBENCH_ADB_PATH`。模型使用本机 Codex 已登录账号与当前模型，需要联网并消耗正常模型用量。

工作台调用 `android-walkthrough 1.0.1`，自动观察实际页面、逐步操作、登记模块和页面状态，并按真实跳转生成模块流程 PNG。模型默认接收精简控件表，必要时从已保存观察读取缩略图；原始 PNG/XML/JSON、研究地图和操作耗时保留在项目内。结果先暂存，只有点击「确认加入项目资料」才写入资料库。确认后的实机图片与商店宣传图通过命名及走查索引区分，可以在后续 F1、竞品分析、原型与需求任务中显式选用。

遇到系统权限、登录、选择器、购买/试用、设备断开等阻塞时，任务会说明原因并暂停。你在手机上处理后点击继续；新一轮先观察当前位置，沿用地图和编号，不重放旧点击。本轮默认最多 60 次动作、10 分钟，可在保留已采集证据的基础上继续下一轮。停止、服务重启和项目包导入都不会自动重新操作设备。

实机图可在窗口直接预览，支持下载含原始证据的 ZIP。暂存目录位于 `workbench/data/scrapes/<项目ID>/android-<会话ID>/`，会随完整项目导出、回收站和恢复保留；导入项目包会生成新的会话 ID 并要求手动续跑。模型执行日志、连接配置和凭据不随项目包导出。

EXE 固定使用随包的 `packages/android-walkthrough/skill/`，不依赖作者电脑或个人 Skill。源码运行优先使用本机已安装的 `android-walkthrough`，再使用仓库副本；`WORKBENCH_ANDROID_SKILL` 可显式指定完整新版目录，无效时提示错误。旧版 `packages/android-capture/skill/` 保留用于兼容已有证据。自动执行通过受限 MCP 工具桥调用固定后端，不开放任意脚本或设备 shell；原有文档生成流程不变。

这项能力是按当前范围执行的自动走查，未观察页面、阻塞模块和不确定跳转会保留缺口。流程图文件校验通过不能代表全 App 已完整覆盖、真实 SDK 测试通过或商业效果成立。接入细节与验证范围见 [实机截图功能说明](../docs/WORKBENCH-ANDROID-CAPTURE.md)。

## 产品版本与文档版本

- “产品版本”是一次发布或迭代，例如 V1.2.0；它归类资料、评论采集、任务和交付物。
- 交付物页面里的 V1、V2 是同一份 Markdown 的编辑修订历史，两者互不替代。
- 当前范围为某产品版本时，自动检索只使用产品级资料和该版本资料，避免其他版本内容混入。
- 用户手动勾选其他版本资料视为明确覆盖，仍会写入本次来源快照并显示版本归属。
- 新品分析可以先按产品级生成；进入实际开发迭代后再创建版本，不增加无意义的流程门槛。

任务在待执行、排队或生成过程中可以取消。取消、失败和服务重启中断都不会删除任务包与输入快照；打开任务，点击「恢复为待执行」即可重新生成或导入结果。正在运行的进程尚未完全停止时，系统会要求稍后再恢复，避免旧结果误写。

## 编辑与版本

- 点击「编辑正文」修改当前 Markdown，填写修改说明后保存；
- 保存不会覆盖历史版本，点击「版本记录」可以查看或恢复任意旧版；
- 恢复旧版也会创建一个新版本，原有版本链不会被改写；
- 已确认交付物只要发生编辑或恢复，就自动回到待评审草稿，需重新确认；
- 下载的 Markdown 和后续项目检索始终使用当前版本，历史版本不会进入 RAG。
- 正文中的 `![说明](asset://图片ID)` 会在预览中显示项目图片；Word/PDF 导出和项目包导入会重映射图片 ID，避免绝对路径失效。
- 资料目录可预览和删除未被正文、历史版本或任务引用的项目图片；被引用图片会被安全阻止删除。
- 资料库支持按分类筛选和名称搜索；图片使用缩略图网格并支持二级分类筛选，分类会随完整项目导出与导入保留。
- 工作流状态由工作台管理；`status`、`reviewed_at` 不再写进 Markdown 正文。其他文档元数据在预览中默认折叠。

## 定位批注与修订

- 将鼠标移到正文的标题、段落、引用、表格或代码块旁，点击「添加批注」；
- 每条批注记录修改位置、原文摘录、动作（新增/修改/删除/压缩/保留）、具体意见、提出人和处理状态；
- 批注绑定创建时的文档版本。正文产生新版本后，旧批注只保留为历史记录，不会误用于新版本修订；
- 「按意见准备修订版」只使用当前版本仍处于待处理状态的批注，并要求模型保持未批注内容、遵守“保留”和“删除”等动作约束；
- 批注不会写进交付物正文。修订结果是带父任务、来源版本和修订原因的新任务；新版成功生成后，参与本次修订的批注自动关闭。
- 当前版本有待处理批注或无法追溯的 `[Sx]` 时，交付物不能确认。

## 任务记录与模式

- 每个任务保存“生成时模式”，项目以后切换快速/完整模式不会改写历史任务；
- 修订任务显示修订版本、父任务和来源正文版本；
- 交付物页面默认只显示各修订分支的最新版，也可查看全部、待处理、已确认或已归档任务；
- 归档只隐藏任务，不删除执行记录、来源快照或交付物。

## 删除项目

在「项目背景」页面底部点击「删除这个项目」，并输入完整项目名称确认。运行中或排队中的项目不能删除，须先停止生成任务。

删除后项目会从工作台和 SQLite 当前数据中移除，但系统会先把项目记录、资料、任务包、交付物、全部历史版本和批注保存到：

```text
workbench/data/trash/<时间>-<项目ID>/
  project-export.json
  uploads/
  runs/
  scrapes/
```

侧栏「项目回收站」可以恢复项目。永久删除仍需再次输入完整项目名称；永久删除后不可恢复。

## 项目导出与导入

- 项目页或「资料」页点击「导出完整项目」，得到一个 `workbench-project-v1` ZIP；数据结构版本为 2，包含背景、产品版本、资料关系、图片、任务包、交付物修订、批注、评审和评论采集记录，同时兼容导入旧结构版本 1。
- 侧栏「导入项目包」会创建一个新的项目副本，不覆盖现有项目。ZIP 会在服务端校验大小、路径和 SHA-256；导入中的排队/运行任务会标记为中断，需要重新开始。
- 项目包不会包含 Codex 配置、Lanhu 凭证、Cookie、Token、向量索引或浏览器缓存。

## 竞品资料采集

### 地区与收入资料

- 「找竞品」的搜索市场可选 **全球（多市场合并）**：合并美国、英国、德国、日本、印度、印度尼西亚、巴西、沙特八个常用市场，按平台＋应用 ID 去重。它不是所有国家或全球榜单；评分、价格等仍保留具体详情市场，实际成功与失败国家分别显示。
- 单次全球搜索最多两个市场子进程并发，单市场约 12 秒、整批约 55 秒调度与执行预算（极端另有进程清理时间）。只缓存成功的具体市场；重试不以美国结果补足失败市场。
- 采集页的「全球（常用 8 市场）」展开实际国家供你调整，并显示竞品数×市场数×每国评论上限。多市场会增加采集与翻译时间；每款最多翻译前 500 条，更多仍保留原文。
- 候选卡的「查看收入来源／补充」提供 Sensor Tower、AppTweak、AppMagic 入口及应用 ID 复制。入口不是已验证的应用收入详情页，不构造未经核实的深链，也不自动登录或调用收费 API。
- 收入数值可人工按来源保存：金额或区间、币种、统计起止、地区、收入类型（订阅/IAP、广告、明确含广告合计等）、净/毛口径、估算/披露性质、来源链接和查看日期。保存为当前项目/版本的独立 Markdown 资料，保留人工记录、未自动核验的标记，可在后续任务中选取并随项目包迁移，不自动改写已有交付物。
- 收入地区的「全球」只在数据源确实标明全球时填写，不能把商店八市场样本当成全球收入。缺失不是零；不同周期、币种、地区和净/毛口径不自动合计。

截至 2026-10-21 核实的来源边界：[Sensor Tower Ad Monetization](https://sensortower.com/blog/ad-monetization-app-analysis-top-ad-publishers) 已提供广告收入相关报告，访问和应用覆盖仍须核对权限；[AppTweak Market Intelligence](https://www.apptweak.com/en/market-intelligence) 有免费页面能力，而 [官方 API](https://developers.apptweak.com/reference/overview) 需要单独授权；[AppMagic](https://appmagic.rocks/) 可用于 IAP 市场资料核对。本机尚未接入这些收入 API，未取得 GBA 单应用可核实的收入数值，不会从安装量推算补写。

竞品可通过「找竞品」搜索商店候选，也可直接填写已知链接，最终均由用户手动选定。搜索不自动推荐评分或替你选择，不生成评论观点分析；展开某一候选才补取其详情，点击采集后才下载所选竞品的截图与评论。工作台调用桌面工具的 `app.scrapers.scrape_google_play` / `scrape_app_store` 函数采集原始评论，并复用同一个隔离 Python 环境读取指定市场的商店信息和宣传截图。Google Play 可读取 Short description 与 Full description；App Store 使用公开 Lookup 结果，Subtitle 未返回时明确留空，不用其他字段猜测。

“同时生成简体中文译文”默认勾选：优先读取桌面工具本机已有的 DeepSeek 配置，以带 index 的小批次 JSON 保持评论与译文一一对应；格式异常时自动拆小批重试，最终才回退 Google 翻译。原评论始终保留在 `content` / `original_content`，译文只写入 `translated_content`。已入库的评论 CSV 可以在卡片预览中点击「补充中文翻译」，每次最多处理 500 条；纯表情和已经是中文的评论不重复翻译。配置和 API 都不返回原始密钥。

工具目录配置保存在本机 SQLite 的 preferences 中，只记录目录和 Python 路径。工作台与采集器之间的 JSON 子进程协议固定为 UTF-8/ASCII 安全输出，评论中的 emoji、中文和其他非 GBK 字符不会导致 Windows 编码失败。批量采集按竞品逐个执行，单项可以取消或失败后重试；采集完成后先显示长短描述、评论数、译文数和截图数，用户确认后才把商店信息 Markdown、评论 CSV 和截图写入项目资料。空结果、超时、工具缺失和异常输出都会保留为明确状态，不生成伪造资料。

## 轻量质量校验

交付物生成、导入、编辑和恢复后都会重新执行确定性检查。错误会阻止「确认这份交付物」，提示只作为建议，不会阻塞。校验结果只显示在交付物页面，不写入正文，也不会进入全局知识库。

## 阶段产物与按需任务

核心内容保持三类：产品方案、原型与需求、验收预期；能放在已有产物中的内容不额外拆文件。五阶段导航用于定位当前工作，不自动审批，也不要求每轮跑全部能力。

### F1 新品需求分析

沿用 Heart Rate 的产品故事，覆盖行业与市场、用户、3–5 个竞品差异、定位、V0 范围、产品功能框架、4–8 个核心模块、主要流程和商业化。F1 不生成平台、权限、数据或政策章节；具体权限交互只在 F2 对应页面需要时说明。默认上限为 16,000 个中文字符，不再压缩成一页定义卡。

F1 默认拆为 `F1-1 品类与用户`、`F1-2 竞品差异`、`F1-3 定位与版本范围`、`F1-4 功能框架与核心模块`、`F1-5 流程、商业化与 PRD 交接`。后一章只在所需前章已确认后开始。全部章节确认后，点击「合并完整 F1」：系统只统一引用编号和章节顺序，不再调用模型重写正文。任意章节产生新版后，完整 F1 会提示重新合并。

新建 F1 时，自动检索只使用用户输入和当前项目上传资料；历史 F1、旧 PRD 和其他已确认交付物不会自动作为当前新品事实。确实需要参考旧文档时，再在任务准备页手动勾选，并把它当作待核对资料。

### F2 核心 PRD

保留 F2 标识，内容为原型与需求说明。按当前原型、本轮模块和确认范围组织，不以 3–5 个页面或 8,000 字裁掉必要规则。说明按业务主题写条件、操作、结果和适用的返回 / 失败 / 恢复；跨页面规则集中维护并引用 RULE-xx。页面用中文名＋稳定 ID，区分页面、弹窗、局部状态和系统说明。独立 PRD 按实际交接需要维护，避免与原型旁注重复成两套事实。

单次生成预算为 24,000 个中文字符；完整基线超出时，按模块分别处理并沿用已有编号，不为缩短篇幅删除已确认页面和规则。指定的长资料每份最多带入 12,000 字，按本轮范围选择相关段落并保留原文位置；任务包会明确标出局部读取范围。

### 六个按需任务

| 任务 | 交付 |
|---|---|
| 公共规则 | 跨页面规则、来源及同步范围 |
| 功能流程与页面状态 | 分模块流程＋单一页面状态清单 |
| 原型制作交接 | 外部制作清单、页面旁注草稿与待同步位置 |
| 评审修改 | 实际意见、影响矩阵、本轮修订正文及同步情况 |
| 全局一致性检查 | 当前原型、需求、流程、规则、编号和验收之间的可定位差异 |
| 产品验收用例 | 按模块生成“验收场景｜操作步骤｜预期结果”三列表，稳定 ID 在场景内 |

原型交接只在工作台内形成文档；实际 Figma / Axure 修改由外部执行。未经实际写入和核验的内容保持待同步，不声称已完成画面或视觉检查。产品验收用例只写预期，不混入实测状态。

### F3 开发验收清单（可选实测）

开发前填写预期，开发后在同一份文档填写实测、日志、截图、问题、修改和复测。默认最多 5,000 个中文字符。

### 多文档规则与变更

来源顺序为当前用户确认 → 当前实际材料或行为 → 已接受的项目文档 → 历史记录 → 通用模板。意图与原型或实现有差异时列出差异，不把新确认当成实际已改。

公共规则变化后，先列影响范围，再同步画面、旁注、需求、流程和验收预期，检索旧口径并复查。文件名为“正式”或“最终版”仍可能含旧规则；全局一致性任务按内容核对。历史送审快照只作参考，不恢复已后置功能。业务评审与静态检查、结构回读、截图查看、真机测试、商业效果分开报告。

### 完整埋点方案（可选）

基于 F2、蓝湖原型快照、截图或交互资料生成完整埋点设计。蓝湖由当前会话通过 Lanhu MCP 只读读取，再以脱敏 Markdown 快照导入项目；工作台不会猜测页面，也不会保存蓝湖凭证。方案覆盖事件、参数、枚举、权限、异常、漏斗、隐私和 F3 验收映射，默认输出中文 Markdown，单份上限 20,000 个中文字符。

在「能力与工具」页的 Lanhu MCP 卡片中点击「配置 / 重新检测」，工作台会默认读取本机 `~/.codex/config.toml`，也可以指定配置文件路径。它只保存启动配置，不保存 Cookie、Token 或其他认证值。连接检测通过后，当前会话完成蓝湖读取，再使用 `POST /api/lanhu/snapshot` 导入快照，字段为 `project_id`、`url` 和 `pages`；每个页面可提供 `id`、`name`、`states`、`text`。服务端只保留蓝湖链接中的稳定导航标识，会过滤邀请链接里的 Token 等敏感参数。

## 资料规则

- 被勾选的资料必须出现在交付物的资料索引中，并在相关结论旁引用。
- 引用已有交付物时，工作台会展开它实际使用的底层来源并重新编号；生成或编辑结果出现快照外编号时拒绝保存。
- 不把整份 CSV、日志或研究原文复制进正文。
- 图片原文件保存在 `workbench/data/uploads/<项目ID>/`，生成时通过 Codex CLI `--image` 作为视觉输入。
- 扫描 PDF 仍需先 OCR。
- 项目资料、数据库、运行记录和截图不会进入 Git。

## 数据位置

```text
workbench/data/
  workbench.sqlite3
  index/                    # 项目隔离向量索引与 manifest
  uploads/<项目ID>/
  scrapes/<项目ID>/<采集任务ID>/
    request.json
    reviews.csv
  imports/<导入任务ID>/       # 导入过程临时目录，完成后自动清理
  runs/<任务ID>/
    任务包.md
    执行记录.json
    model-output.md
    交付物.md
    交付物-v0001.md
    交付物-v0002.md
```

本地文件不加密，按电脑文件权限保护。点击「开始生成」会把任务包及本次引用的图片发送给 Codex 模型服务。另有独立的联网边界：商店搜索与采集会访问相应公开商店；勾选评论翻译时，会把待翻译的评论原文发送给本机已配置的 DeepSeek 服务，失败时可能回退 Google 翻译。不需要翻译时可取消勾选。

默认检索模式为 `hybrid`。需要排查或临时禁用向量检索时，可以把环境变量 `WORKBENCH_RETRIEVAL_MODE` 设为 `keyword`；设为 `shadow` 时会执行 Hybrid 对比，但界面仍返回关键词结果。
