# 本地产品工作台

V0.7 面向小型出海 App 团队。用户给出的新品默认就是要做，工作台只保留三份主交付物：

```text
F1 新品需求分析
  → F2 核心 PRD
  → F3 开发验收清单
```

竞品评论 CSV、政策来源、技术日志、截图和研究资料直接进入这些文档。快速模式不生成用户访谈、假设验证、风险清单、技术 Spike、Gate 或条件闭环。

## 启动

在仓库根目录运行：

```powershell
.venv\Scripts\python.exe workbench\app.py
```

打开 **http://127.0.0.1:8765**。也可以运行 `workbench/start.ps1`。模型生成需要联网且本机 Codex 已登录。

## 使用步骤

1. 新建项目；日常使用「快速迭代」。
2. 在「项目背景」填写产品方向、目标平台、团队和本轮范围，不知道的可以留空。
3. 在「资料与检索」导入资料。支持 MD、TXT、CSV、JSON、文本 PDF、DOCX、PNG、JPG、JPEG、WEBP；每份最大 12 MB。
4. 在「任务」选择 F1、F2 或 F3。
5. 准备任务时勾选最多 12 份要写进文档的资料。截图会作为图片输入，其他资料会解析为文本。
6. 检查任务包后开始生成；结果先作为待评审草稿。
7. 在交付物预览页，可对具体章节、段落或表格添加批注，也可以直接编辑 Markdown 正文。
8. 对待处理批注点击「按批注精确修订」；新版生成成功后，本次使用的批注自动标记解决。
9. 评审确认后，该交付物才会自动进入后续项目检索。

任务在待执行、排队或生成过程中可以取消。取消、失败和服务重启中断都不会删除任务包与输入快照；打开任务，点击「恢复为待执行」即可重新生成或导入结果。正在运行的进程尚未完全停止时，系统会要求稍后再恢复，避免旧结果误写。

## 编辑与版本

- 点击「编辑正文」修改当前 Markdown，填写修改说明后保存；
- 保存不会覆盖历史版本，点击「版本记录」可以查看或恢复任意旧版；
- 恢复旧版也会创建一个新版本，原有版本链不会被改写；
- 已确认交付物只要发生编辑或恢复，就自动回到待评审草稿，需重新确认；
- 下载的 Markdown 和后续项目检索始终使用当前版本，历史版本不会进入 RAG。
- 工作流状态由工作台管理；`status`、`reviewed_at` 不再写进 Markdown 正文。其他文档元数据在预览中默认折叠。

## 定位批注与修订

- 将鼠标移到正文的标题、段落、引用、表格或代码块旁，点击「添加批注」；
- 每条批注记录修改位置、原文摘录、动作（新增/修改/删除/压缩/保留）、具体意见、提出人和处理状态；
- 批注绑定创建时的文档版本。正文产生新版本后，旧批注只保留为历史记录，不会误用于新版本修订；
- 「按意见准备修订版」只使用当前版本仍处于待处理状态的批注，并要求模型保持未批注内容、遵守“保留”和“删除”等动作约束；
- 批注不会写进交付物正文。修订结果是带父任务、来源版本和修订原因的新任务；新版成功生成后，参与本次修订的批注自动关闭。
- 当前版本有待处理批注或无法追溯的 `[Sx]` 时，交付物不能确认。

## 任务记录与模式

- 每个任务保存“生成时模式”，项目以后切换快速/完整模式不会改写历史任务；
- 修订任务显示修订版本、父任务和来源正文版本；
- 交付物页面默认只显示各修订分支的最新版，也可查看全部、待处理、已确认或已归档任务；
- 归档只隐藏任务，不删除执行记录、来源快照或交付物。

## 删除项目

在「项目背景」页面底部点击「删除这个项目」，并输入完整项目名称确认。运行中或排队中的项目不能删除，须先停止生成任务。

删除后项目会从工作台和 SQLite 当前数据中移除，但系统会先把项目记录、资料、任务包、交付物、全部历史版本和批注保存到：

```text
workbench/data/trash/<时间>-<项目ID>/
  project-export.json
  uploads/
  runs/
```

侧栏「项目回收站」可以恢复项目。永久删除仍需再次输入完整项目名称；永久删除后不可恢复。

## 三份交付物

### F1 新品需求分析

沿用 Heart Rate 的产品故事，覆盖行业与市场、用户、3–5 个竞品差异、定位、V0 范围、产品功能框架、4–8 个核心模块、主要流程和商业化。F1 不生成平台、权限、数据或政策章节；具体权限交互只在 F2 对应页面需要时说明。默认上限为 16,000 个中文字符，不再压缩成一页定义卡。

### F2 核心 PRD

只写当前版本真正要实现的 3–5 个页面或功能，包括交互、规则、状态、异常恢复、英文 UI copy 和验收。默认最多 8,000 个中文字符。

### F3 开发验收清单

开发前填写预期，开发后在同一份文档填写实测、日志、截图、问题、修改和复测。默认最多 5,000 个中文字符。

## 资料规则

- 被勾选的资料必须出现在交付物的资料索引中，并在相关结论旁引用。
- 引用已有交付物时，工作台会展开它实际使用的底层来源并重新编号；生成或编辑结果出现快照外编号时拒绝保存。
- 不把整份 CSV、日志或研究原文复制进正文。
- 图片原文件保存在 `workbench/data/uploads/<项目ID>/`，生成时通过 Codex CLI `--image` 作为视觉输入。
- 扫描 PDF 仍需先 OCR。
- 项目资料、数据库、运行记录和截图不会进入 Git。

## 当前边界

| 能力 | 当前实现 |
|---|---|
| 项目与背景 | SQLite 持久化；模式、平台、团队、周期和上下文 |
| 文档与截图 | 原文件保存、文本解析、图片校验、SHA-256 去重 |
| 项目检索 | 当前项目上传资料和已确认产物；草稿不自动进入 |
| 生成 | 本机 Codex CLI、中文 Markdown、一次一个任务 |
| 编辑与评审 | 内容块定位批注、批注精确修订、来源完整性检查、Markdown 正文编辑、版本记录与恢复；待评审、需修改、已确认 |
| 任务恢复与整理 | 取消/失败/中断恢复、修订父子链、生成时模式、筛选与非破坏归档 |
| 项目删除 | 项目名二次确认、运行状态拦截、本地完整备份、回收站恢复与永久删除 |
| 评论采集 | 可导入桌面采集器 CSV；自动启动采集器尚未接入 |
| RAG | 工作台为关键词检索；Product KB MCP 的 Hybrid RAG 独立可用 |
| 导出 | Markdown；Word、Excel、Axure、Figma 尚未接入 |

完整研究模式和历史 T1–T4 继续保留用于明确要求的正式研究，不是日常默认流程。完整模式仍可显示条件管理；快速模式隐藏该入口。

## 数据位置

```text
workbench/data/
  workbench.sqlite3
  uploads/<项目ID>/
  runs/<任务ID>/
    任务包.md
    执行记录.json
    model-output.md
    交付物.md
    交付物-v0001.md
    交付物-v0002.md
```

本地文件不加密，按电脑文件权限保护。只有开始生成时，任务包和选中的图片才会发送给模型服务。
